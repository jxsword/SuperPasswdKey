## 1. 解析管道

```mermaid
flowchart LR
    S1[".env 文件/目录递归"] --> P1[DotenvParser]
    S2["通用 CSV\n(列映射向导)"] --> P2[CsvParser]
    S3["Bitwarden JSON\n(核心字段)"] --> P3[BwJsonParser]
    S4["当前进程环境变量\n(内存枚举,不落盘)"] --> P4[EnvSnapshotParser]
    S5["任意文件/脚本\n(gitleaks 规则 TOML 内嵌 235 条)"] --> P5[RuleEngine]
    P1 & P2 & P3 & P4 & P5 --> F["统一 Finding\n{source,file,line,ruleId,secret,fingerprint}"]
    F --> D1{"L1 值哈希精确匹配"}
    D1 -->|重复| TAG1[duplicate 标记]
    D1 -->|唯一| D2{"L2 URL+用户名 合并"}
    D2 -->|同目标| TAG2[merge 标记]
    D2 -->|新条目| D3{"L3 指纹/前缀\n(私钥指纹/key 前缀)"}
    D3 -->|疑似副本| TAG3[conflict 标记]
    D3 -->|新| NEW[新条目候选]
    TAG1 & TAG2 & TAG3 & NEW --> CLS["分类聚类\n来源类型/项目路径/规则名"]
    CLS --> DRY["sp import --dry-run 预览"]
    DRY --> IMP["导入 + 需人工抽查清单"]
```

原则：**冲突不清除**——全部保留打标记人工裁决（基线§4.3）。

## 2. 类设计（PlantUML，渲染物 diagrams/05_importer.svg）

```plantuml
@startuml
interface SourceParser {
  +parse(input) : Vec<Finding>
}
class DotenvParser
class CsvParser {
  -column_mapping : ColumnMap
}
class BwJsonParser
class EnvSnapshotParser {
  note: std::env::vars 枚举\n纯内存,无临时文件
}
class RuleEngine {
  -rules: Vec<GitleaksRule>  // TOML 静态内嵌
}
SourceParser <|.. DotenvParser
SourceParser <|.. CsvParser
SourceParser <|.. BwJsonParser
SourceParser <|.. EnvSnapshotParser
SourceParser <|.. RuleEngine
class DedupEngine {
  +l1_value_hash() / l2_url_user() / l3_fingerprint()
}
class ImportReport {
  +counts / groups / conflicts / manual_review[]
}
class EntryCandidate
DedupEngine ..> EntryCandidate
SourceParser --> F0 : 产出
F0 : Finding {source,file,line,ruleId,secret,fingerprint}
DedupEngine --> ImportReport
@enduml
```

## 3. 环境变量快照（SP-F-401④）

`std::env::vars()` 进程内枚举 → 逐值跑 RuleEngine → Finding（source="env"）；**无临时文件**（红线 #4、基线§4.5#6——gitleaks/trufflehog 均不支持 env 源，此为自研增量）。

## 4. 范围声明

Bitwarden JSON 仅核心字段（login/uri/notes/custom fields/TOTP），附件与 passkey 后置（SRS §2.3）；1pux 解析器 v0.2。分类器不做语义猜测（按来源路径聚类），机器分类 v0.2+。

## 5. 测试挂钩

每解析器 10+ 样例单测；proptest（合法输入不崩溃/往返一致）；三级去重构造样例断言（T-402）；dry-run 无副作用断言。
