# 12 填充引擎与表单匹配（content script + host URL 匹配）

- 状态：v1.0（2026-10-27）｜追溯：SP-F-704、SP-F-705、SP-F-706｜决策：DR-006
- 参照：keepassxc-browser 表单探测（GPL-3.0，参照思想自实现）、Bitwarden clients 同名逻辑；本项目基线 B4 §8.1 已声明填充精度是长期工程，本期只做**单页登录表单**最小验收。

## 1. 职责划分

| 层 | 职责 | 理由 |
|---|---|---|
| content script | DOM 表单探测（找字段）、接收 fill 命令、写值 + 事件派发 | 只有 content script 能碰 DOM |
| service worker | 会话/端口管理、向 host 取匹配列表、把机密从 host 中转到 content script（内存直传，不落任何 storage） | 管道只有 SW 持有 |
| host | URL 匹配引擎（页面 URL → 条目列表）、机密单条取回 | 匹配规则纯函数在 Rust 侧单测/回归（单源）；扩展端零业务逻辑 |

## 2. 表单探测（扩展端，纯函数 + DOM 适配分离）

探测输入 = 当前文档的可见输入控件描述符列表 `{index, type, name, id, autocomplete, formIndex, visible, rect}`；探测输出 = 候选登录字段组。**规则集（MVP）**：

1. 密码字段：`input[type=password]` 且可见（offsetParent 非空 + rect 面积 >0）。
2. 用户名字段：同一 `<form>`（无 form 则取同容器 300px 视觉半径）内、位于密码字段**之前**（DOM 序）的第一个可见输入，type ∈ {text, email, tel, 空省略}；排除 `type=search|hidden|checkbox|radio|submit|button`。
3. 辅助信号（加分不改名）：`autocomplete=username` 强制采纳；`autocomplete=one-time-code` 标记为 TOTP 填充目标（可选填充）。
4. 排除：`name/id` 匹配 `search|query|captcha|otp_only` 语义的字段不作用户名候选。
5. 多密码字段（注册/改密页）→ 识别为"非单页登录"，本期不填充（返回空结果并提示）。

纯函数（`extension/src/content/detect.ts`）吃描述符不吃 DOM，vitest 直测；DOM 适配层（`collect.ts`）薄壳不进单测。

## 3. URL 匹配引擎（host 侧，SP-F-706）

输入 = 页面 URL + 库条目 url 字段。规则（MVP，无 PSL 依赖）：

1. scheme 白名单：`http`/`https`；条目 url 无 scheme → 仅当与页面 host 相同才可能匹配。
2. host 归一：小写、去末尾点；端口参与比较（省略端口 = 该 scheme 默认端口）。
3. 打分：精确 host(含端口) 相同 = 100；页面 host 与条目 host 同属"末两段相同"的 base domain = 60（`login.example.com` 匹配 `example.com` 条目；**不**匹配 `evilexample.com`——比较按段对齐不做子串）；scheme 不同（http vs https）扣 10。
4. 输出按分降序，同分按标题字典序；无匹配返回空数组（不猜测）。
5. 已知局限（backlog）：多级 TLD（co.uk）会误判 base domain；引入 publicsuffix crate 后升级。

纯函数 `crates/sp-nmhost/src/match_url.rs`，Rust 单测覆盖上表全部分支 + 反例（`evilexample.com`、scheme 混用、端口不一致）。

## 4. 填充语义（content script）

- 值写入：优先原生 setter（`HTMLInputElement.prototype` 的 value setter 经 `call`），React/Vue 受控组件兼容；随后派发 `input` 与 `change` 事件（`bubbles: true`）。
- 密码填充 = `sp.get-secret(field=password)` 单条取回 → 立即写入 → 变量置空；TOTP 仅当页面存在 `autocomplete=one-time-code` 输入且条目含 otp 属性（`sp.get-secret(field=totp)`）。
- 填充触发：popup 选择条目 → SW 向活动标签页发 `sp.fill` 消息 → content script 执行；**不做**页面内自动注入浮层（backlog）。
- 内存卫生：content script 收到机密即用即弃（函数作用域内清空引用），不存任何全局/扩展存储（SP-F-707）。

## 5. popup（SP-F-705）

- 状态条：锁定 → 主密码输入框 + 解锁按钮（发 `sp.unlock`）；解锁 → 当前页匹配列表（`sp.get-logins`）+ 搜索框（本地对 title/username 过滤，不发请求）。
- 每条目：`填充` 按钮（密码 [ +TOTP ]）；条目多字段信息不展示（最小化攻击面）。
- 无库/多库：本期单默认库（config.toml），`sp.status` 展示库路径提示。

## 6. 测试与验收（T-704~706）

- vitest：探测规则集（§2 全分支：密码字段可见性、用户名启发式、autocomplete 覆盖、多密码字段拒绝、search 排除）。
- Rust：URL 匹配引擎（§3 全分支）。
- Chrome 手工清单（docs/reviews/，签字项）：本地 demo 页真实登录填充（B4 出口）、错误密码提示、锁定后重新解锁、无匹配页面空列表。
