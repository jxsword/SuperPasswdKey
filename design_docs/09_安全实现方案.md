# 09 安全实现方案（加密算法/存储格式/复杂度/进程与文件保护）

- 状态：v1.0（2026-10-26，经两轮复审修正 13 项）｜追溯：SP-F-101/105、SP-N-301~312、SP-C-101(#5#6#7)
- 数据来源：docs/research/分报告A§1.4（1Password 白皮书 R0.5.2）、分报告B§1.4（Bitwarden 白皮书）、分报告C§1（KDBX4 规范 keepass.info 核实）——均为 2026-10-25 实测核实

## 1. 四产品加密架构对比

| 维度 | 1Password | Proton Pass | Bitwarden | KeePass KDBX4 | **SuperPasswdKey v0.1** |
|---|---|---|---|---|---|
| KDF | PBKDF2（慢哈希专章）+ Secret Key 组合 | bcrypt | PBKDF2 / Argon2id + HKDF 512-bit 拉伸 | Argon2d/2id 或 AES-KDF（m/t/p 可配） | **Argon2id 唯一**（m≥64MiB 硬下限，init 校准 ~700ms） |
| 对称加密 | AES-256-GCM | AES-256-GCM | AES-256-CBC + HMAC-SHA256（cipherstring） | AES-256-CBC 或 ChaCha20（内层流） | 跟随 KDBX4 规范 |
| 完整性 | AEAD 内建 | AEAD 内建 | Encrypt-then-MAC | **强制 HMAC-SHA-256 头认证 + 分块 EtM** | 同 KDBX4 |
| 密钥结构 | 账户→库→条目三层 | Item→Vault 信封 | 用户/组织密钥体系 | 单复合密钥 | 复合密钥（KDBX 语义） |
| 第二因子 | Secret Key（打印字母串，不可自定义，绑定账号） | 无独立文件 | 无独立文件 | keyfile 文件 | **keyfile（可自定义/可轮换/任意文件兼容）** |
| 服务端 | 云端仅密文 | 云端仅密文（SRP 认证） | 云端仅密文 | 无服务端 | 无服务端（F6 后置） |

选型理由：DR-003 兼容优先 → 库内算法完全遵循 KDBX4 规范（获得全生态互操作）；KDF 弃 PBKDF2/bcrypt 只用 Argon2id（LastPass 低迭代 + 内存硬抗 GPU/ASIC，红线 #6）；自有加密产物（F10 归档）唯一使用自有 AEAD（age：XChaCha20-Poly1305 + scrypt 口令钳）。

## 2. 存储格式规范

| 对象 | 格式 | 安全属性 |
|---|---|---|
| 账户信息 | 单一 `.kdbx`（KDBX4/4.1）：头部（明文版本/参数）+ 加密内部头（附件入此）+ 分块密文流 | 格式层全加密；元数据（标题/URL）在密文内（红线 #4） |
| **密钥文件** | **裸 32B CSPRNG**（getrandom，OS 熵源）生成；**接受任意文件**（SHA-256(内容) 派生，KeePass 兼容——用户可用照片等）；raw/hex 双读取 | 无加密无结构——安全完全依赖物理保管渠道；与库**分渠道分发**（绝不同目录/同云盘路径）；轮换 = 重开库全量重存 |
| 复合密钥 | `SHA-256(SHA-256(password) ‖ SHA-256(keyfile))` → Argon2id | keepass 组合语义（互操作必须） |
| 配置 | `config.toml` 明文（默认库路径/keyfile 路径/clip 超时/**完整性基线哈希**） | 不含任何密钥材料 |
| 导出归档 | zip + age（scrypt 口令钳） | **官方 age 工具独立可解密**（逃逸通道：产品消失数据可取回，F10 验收标准） |

## 3. 时间/空间复杂度与实际资源分析（⚠️ 估算值，H1 spike 实测回填 SP-N-301/302）

| 操作 | 时间复杂度 | 实际估算 | 内存 |
|---|---|---|---|
| Argon2id 派生 | f(m,t,p)，内存硬设计（抗 GPU/ASIC 的时间-内存权衡） | m=256MiB/t=4 单核 ≈0.5–1s（init 校准到 ~700ms）；期间单核 100% | 峰值 ≈ m（256MiB） |
| 对称解密（AES-NI/ChaCha20） | O(n) | 1–5 GB/s（AES-NI）/ 200–500MB/s（ChaCha20 软实现）→ 1MB 库 <5ms | O(1) 流式分块 |
| HMAC-SHA-256 分块校验 | O(n) | ~0.5–1 GB/s | O(块) |
| 空间开销 | 密文 ≈ 明文 + 每块（1MiB）32B HMAC + 头部 ~1KB | 膨胀 <0.01%（1MB 附件） | — |
| **解锁全流程**（1000 条目+10×1MB 附件库） | KDF ~700ms + 解密/解析 <1s | 总计 ≈1.7–2s | **峰值 ≈350–400MiB**（KDF 256MiB + XML DOM 2–4× 数据量 + 密钥缓冲）；稳态 ≈ 明文×3 |
| CPU 特征 | 解锁期单核脉冲；稳态操作可忽略 | — | — |

## 4. 进程保护（防主密码/密钥泄露）——诚实威胁边界

**边界声明**：同 OS 用户态高权限进程读取另一进程内存无法被应用层完全阻止——1Password/Bitwarden/KeePassXC 同样如此。本方案提供的是**提高攻击成本 + 缩小暴露窗口**，并如实写进双语文档（SP-F-303）。

| 层 | 措施 | 优先级 | 限制（如实声明） |
|---|---|---|---|
| 内存 | 密码/密钥缓冲 `SecVec`（zeroize on drop）；密钥不进日志/错误链 | P0 | — |
| 内存 | **VirtualLock 锁定密钥页**防交换进 pagefile/hiberfil（CVE-2023-32784 泄露路径） | P0 | 最佳努力：内存压力下系统可强制换出；进程崩溃/休眠有残留（休眠安全→建议 BitLocker）；锁失败→警告非致命 |
| 进程 | **SetProcessMitigationPolicy**：ExtensionPointDisable（防第三方 DLL 扩展点注入）+ DynamicCodePolicy（禁运行时动态代码），main 早期调用 | P0 | CFG 因 Rust 生态非 CFG-aware 暂缓（不虚假声明） |
| 检测 | 周期反调试（IsDebuggerPresent/CheckRemoteDebuggerPresent）→ 记录警告+提示风险+安全退出 | P0 | 公开知识可绕过——定位"低成本摩擦+事后告警"，非防护保证 |
| 生命周期 | 无跨进程会话缓存（v0.1）；keepass_ng XML DOM 残留由其内部决定，**未必全量零化**——与 KeePassXC（C++/Qt）同级、优于 KeePass 原版（.NET，CVE-2023-32784）；缓解=尽快 drop 避免克隆 | P0 | 该残留风险如实写入 README |
| backlog | DPAPI 会话缓存（吸取 Bitwarden CVE-2023-27706：本机凭据管理器可被本地攻击者读取——若做，密文须绑定当前用户+机器） | P1 | — |

## 5. 文件保护（防扫描上传/删除/篡改）——诚实威胁边界

**边界声明**：用户态恶意软件（infostealer/ransomware）可读/删任何用户文件，应用层无法阻止上传/删除——各家产品皆然。本方案提供**检测 + 恢复 + 纵深**，防"上传"由架构保证（sp 零网络 + 同步密文由用户自选渠道），防"删除/篡改"由备份恢复。

| 层 | 措施 | 优先级 | 说明 |
|---|---|---|---|
| 检测 | **完整性基线**：config 记录上次成功打开后的库 SHA256；`sp doctor` 命令手动核查；打开**失败**时若磁盘哈希≠基线 → 提示"库已被外部修改且当前不可打开"（退出码 1） | P0 | 打开成功 → 静默更新基线（多设备同步是正常场景，防误报，复审修正 R2-3）；**不能防协同篡改**（攻击者可同改 config）——变更检测非安全边界（R1-3） |
| 恢复 | **自动备份轮换**：每次保存（原子替换完成后）复制到 `<库目录>.sp-backup/<库名>-<UTC时间戳>.kdbx.bak`，滚动保留 10 份、只读属性 | P0 | 备份为密文（云盘同步无害且加分，文档明示供用户知情）；优于 KeePass 生态"用户自觉"备份 |
| 纵深 | 零网络（架构保证不自行上传）；同步渠道密文（F3）；用户建议：BitLocker 全盘（覆盖 hiberfil/pagefile 残留）、云盘 2FA+回收站（坚果云版本历史）、备份介质离线 | 文档 | 应用层无法阻止第三方恶意软件上传/删除——README 双语声明 |
| backlog | ReadDirectoryChangesW 运行期文件监控实时告警 | P1 | — |
