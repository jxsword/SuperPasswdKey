## ④ CI 缓存实施清单（对照 §CI 缓存配方）

| 配方项 | 实施 | 版本/key |
|---|---|---|
| desktop + windows(tag) tauri-cli | `actions/cache` 仅缓存 `~/.cargo/bin/cargo-tauri.exe`（避开与 rust-cache 的 `~/.cargo/bin` 全目录 key 纠缠），miss 才 install | 钉版 **2.12.4**（v0.3.0 本地构建实测版本）；key `tauri-cli-<版本>-windows-x64` |
| windows keepassxc | 弃 choco，改 GitHub 官方便携 zip + `actions/cache` 解压目录；`SP_KEEPASSXC_CLI` 经 `GITHUB_ENV` 递归定位指向解压内层目录（`KeePassXC-2.7.12-Win64/`），规避 zip 顶层目录名耦合 | 钉 **2.7.12**（对齐 choco 2.7.x 绿色基线；2.8.0 刚发布、CLI 行为未回归，暂不冒进）；key `keepassxc-<版本>-windows-x64` |
| android + android-e2e cargo-ndk | 同 tauri-cli 二进制缓存方案 | 钉 **4.1.2**（crates.io 当前稳定版 = 原浮动安装解析值，行为零变化） |
| android-e2e 模拟器 SDK 下载 | `actions/cache` **仅缓存 `system-images`**。配方原列 emulator/platform-tools 一起缓存——首跑实测（PR #54 run 41039822945）：二者是 runner 预装目录（root 属主），恢复时原地覆盖报 `Cannot utime: Operation not permitted` → 整包作废回退预装版 | key `android-sdk-images-api34-…-v2-<runner镜像>`（`$ImageVersion`，缺失回退 unknown；v2 = 与含毒旧条目隔离） |
| android-e2e AVD 冷启动 | 官方 README 快照两步流：AVD cache（`~/.android/avd/*`、`~/.android/adb*`、**`~/.android/debug.keystore`**）→ miss 时生成快照步 → e2e 步 `-no-snapshot-save` + `force-avd-creation: false` 加载；另加陈旧 `.lock` 清理步。首跑实测补充两课：① debug.keystore 不缓存则签名漂移，快照内旧包与新一轮 APK 签名不匹配 → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`；② 缓存路径 bump v2 | key `avd-api34-…-v2-<runner镜像>`；e2e 脚本安装前先 `adb uninstall` 同包名旧应用兜底 |

**冷启动实测校准**：KVM 下冷启动仅 30–40s（配方估算 2–4 min 偏悲观），AVD 快照收益约 20–30s/次，SDK 镜像缓存收益约 1–2 min/次。
| android-e2e Gradle 依赖 | `setup-java` 补 `cache: gradle` | — |
| windows(tag) pnpm | **主动放弃**：首跑实测（PR #54 run 41036909889）PR 运行不执行 pnpm install，pnpm store 目录（`D:\.pnpm-store\v11`）不存在 → setup-node 后置保存路径校验 `##[error] Path Validation Error` → 整个 job 红。收益仅 tag 构建 30-60s，不值得为此引入双 setup-node 步骤；extension job（每次都 install）的 pnpm 缓存保留 | — |
| deny | **按配方不加缓存**；"路径过滤触发"改造本轮未实施——需引入第三方 paths-filter action 且 skipped job 会改变"七 job 全绿"门禁语义，保守维持全量触发 | — |
| rustup 工具链 | 配方标注"可选，避免过度工程可不做"——未实施 | — |

**行为变化提示**：原 e2e 步使用 action 默认 `emulator-options`（含 `-no-snapshot`），即每次全冷启动；现改为快照加载，首跑生成快照、后续跑加速 2–4 min。

**钉版升级路径**：改 workflow 顶层 `env` 三个 `*_VERSION` 即可（版本号即 key 分量，bump 即失效旧缓存）。
