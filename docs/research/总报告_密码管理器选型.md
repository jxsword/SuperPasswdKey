## 1. 背景与调研方法

本项目以「1Password 收费全功能」为基准，评估"直接选用现有软件"与"自研 SuperPasswdKey"两条路线。核心功能定义：

| 编号 | 功能 |
|---|---|
| F1 | 自动保存/浏览器填充 |
| F2 | 本地加解密 |
| F3 | 云端只存密文 |
| F4 | 密钥文件本地 + 主密码不上云 |
| F5 | 跨平台（Win/Linux/Android 必选，macOS/iOS 备选） |
| F6 | 私有部署（或无服务器形态） |
| F7 | CLI |
| F8 | CLI 临时环境变量注入（对标 1Password `op run` 语义） |
| F9 | 批量导入（含散落密钥扫描导入） |
| F10 | 批量导出（默认加密归档 + 可选明文） |

调研方法：

- URL 三件套（官网/官方文档/源码）全部经 WebFetch / curl（HTTP 状态码）/ GitHub API 于 **2026-10-25** 实测核实；可达性受阻的页面（反爬 403、DNS EAI_AGAIN、动态渲染）如实标注核实方式。
- 安全事件经官方公告、NVD/GitHub Advisory API 实测查询与权威安全媒体（Malwarebytes、Ars Technica、WithSecure、Wiz、Unit42、Sophos、Checkmarx 生态等）交叉验证。
- 分报告中未能核实的项（Dashlane 个人档官方价格、LastPass 2021/2023 部分公告原文被 Akamai 拦截 403、proton.me 与 dashlane.com 在执行环境 DNS 不通、Strongbox/KeePassium 精确版本号、坚果云 WebDAV 域名等）均如实继承标注，不凭记忆补数。
- 所有示例命令一律使用占位符（如 `<你的服务令牌>`），不含真实凭据。

## 2. 调研对象条目

### 2.1 1Password（收费全功能基准）

- 三件套：官网 https://1password.com/ ✅（2026-10-25 HTTP 200；中文页 https://1password.com/zh-cn 实测 200）；官方文档 https://support.1password.com/ ✅、开发者/CLI 文档 https://www.1password.dev/ ✅（个别页如 /security-design/ 返回 403 反爬，/security-assessments/ 正常 200）；源码：无（产品本体与 CLI 均闭源）。安全设计白皮书 https://1password.com/files/1Password-White-Paper.pdf 现 301 重定向至在线版 https://agilebits.github.io/security-design/ ✅（当前版本 Release 0.5.2，2026-03-05 更新）。
- 简介：AgileBits 出品的老牌商业密码管理器，2026 年已转型为 "Unified Access" 统一访问平台（密码管理 + 凭证代理 + 特权访问 + SaaS 管理），营销口号 "Secure access for every human and AI agent"；个人/家庭产品线正常销售。
- 加密架构（在线白皮书核实）：Secret Key 机制——注册时本地生成约 128-bit 高熵 Secret Key，与账户主密码组合后经慢哈希（PBKDF2）派生密钥；Secret Key 保存在本地/应急包（Emergency Kit PDF），**不上传服务器**；客户端 AES-256-GCM 加解密，服务端仅存密文（白皮书 "What the server stores" 专章）；账户密钥→保险库密钥→条目密钥分层。
- 收费（/personal 页核实）：Individual $3.99/月（年付促销 $2.99，首年另有 25% 折扣）；Families $5.99/月（最多 5 人）；Business 按报价。14 天免费试用；官方支付仅信用卡/ACH，**不支持支付宝/微信**。
- 国内版现状：无官方国内版，无中国本地化服务器与国内合规主体；官网 zh-cn 中文页可访问但定价仍为美元；国内用户需 Visa/Mastercard 国际卡。
- 版本（2026-10-25）：桌面/浏览器端 8.12.42（2026-10-20）；CLI 2.43.0。
- 安全审计：ISE（2020 渗透测试+代码审查）、Onica（AWS 基础设施评估）、2025-11 起年度渗透测试经 Trust Center 发布、2024-12 起 HackerOne 公开赏金、ISO 27001/27017/27018/27701、SOC 2 Type II。
- 特色专有功能：Secret Key 双因子；1Password Environments（云端 .env 管理）；Shell Plugins（80+ 第三方 CLI 生物识别认证）；Service Account + Connect Server 密钥自动化；Watchtower 安全巡检；通行密钥与 SSH agent 集成。
- F 对照：F1✅（业界最成熟）F2✅ F3✅ F4⚠️（Secret Key 不可自定义"密钥文件"，绑定账号且云端可辅助找回）F5✅（Linux 一等公民）F6❌（纯 SaaS；Connect 仅 secrets API 网关，保险库仍托管在 1Password 云）F7✅（op CLI 2.x 功能最全）F8✅（`op run`/`op inject`/`op plugin run`，本调研标杆）F9⚠️（应用内导入 LastPass/Bitwarden/CSV/1PUX 等十余种来源；CLI 无官方 import 子命令，环境变量扫描导入无官方方案）F10⚠️（1PUX 全量+CSV 仅登录类字段；官方明确 **1PUX/CSV 导出均为明文、不支持设置密码加密**；附件/文档导出支持未见官方说明）。
- 优点：加密架构文档化程度最高；CLI/Secrets Automation 生态全行业最完整；Linux 支持好；审计与合规齐全。缺点：纯订阅制无买断；不支持私有部署；导出无加密选项；国内访问与支付不便。
- 适用场景：个人开发者与中小团队的全功能默认选择；作为本项目「收费全功能」基准完全成立。

### 2.2 Proton Pass

- 三件套：官网 https://proton.me/pass ✅（经外部抓取服务核实可达；**本机直连失败**：DNS 解析 proton.me 报 EAI_AGAIN）；官方文档 https://proton.me/support/pass ✅（同上）；源码 https://github.com/protonpass ✅（android-pass、ios-pass、pass-cli 等；pass-cli 最新 release 2.5.1，2026-10-21，GPL-3.0，Rust 编写，426 stars）。加密方案文档：官方博客 https://proton.me/blog/proton-pass-security-model ✅。
- 简介：Proton（Proton Mail/VPN 同门）2023 年推出的密码管理器，发布时即同步开源客户端并通过 Cure53 审计；主打隐私全家桶集成（SimpleLogin 邮箱别名、Proton Sentinel、2FA 集成 authenticator）。
- 加密架构：分层信封加密——每条目 32-byte 随机 Item Key 加密条目内容，Item Key 再被 32-byte 随机 Vault Key 加密，Vault Key 由用户密钥体系保护（改密/换库无需重加密全部数据）；AES-256-GCM + bcrypt KDF（主密码派生）；服务端认证用 SRP（服务端不掌握明文密码）；全字段端到端加密（含标题、URL、备注）。
- 收费：Free $0（无限密码、任意设备、2 保险库、别名 10 个）；Pass Plus $2.99/月（无限别名/保险库、集成 2FA、1GB 文档存储、**支持 CLI 等进阶功能**）；Pass Family $4.99/月（6 用户）；Proton Unlimited $9.99/月（全家桶）。
- 版本：CLI pass-cli 2.5.1（2026-10-21）；移动/桌面客户端仓库活跃，具体 App 版本号未在本次抓取中固定，不作断言。
- 安全审计：Cure53 2023-07 对浏览器扩展、移动应用与 API 的渗透测试，报告公开 https://cure53.de/pentest-report_proton-pass.pdf ；后续 Recurity Labs 对全部 Pass 应用审计（Proton 社区页面提及）；集团层面 ISO 27001 沿用。
- 优点：客户端全开源 + 公开审计报告；价格低于 1Password；免费档最慷慨；CLI 开源可审计，本项目可参考其 `pass://` 引用与环境变量注入实现。缺点：❌F4 无独立密钥文件机制（主密码即 Proton 账户密码）；❌F6 无自托管（开源的是客户端，服务端仍由 Proton 托管）；主密码与账户密码合一（换主密码=换账户密码）；生态较新。
- F 对照：F1✅（成熟度略逊 1Password）F2✅ F3✅ F4❌ F5✅（Linux 桌面端相对较新）F6❌ F7✅ F8✅/⚠️（`pass://vault/item/field` 引用可注入环境变量或模板文件，官方 GitHub Action（load-secret-action）与 Ansible 插件；机制与 op run 同思路，但生态较新、文档成熟度不及）F9⚠️（应用内 CSV/主流管理器导入；无 CLI import 命令、无环境变量扫描）F10⚠️（CLI 支持 CSV/JSON 导出；加密归档导出、附件全量导出未见官方说明）。
- 适用场景：重视开源与审计、想要 Proton 隐私全家桶的个人/家庭用户。

### 2.3 Dashlane

- 三件套：官网 https://www.dashlane.com/ ✅（经外部抓取服务核实；**本机直连失败**：DNS EAI_AGAIN，curl/WebFetch 均不通）；官方文档 https://support.dashlane.com/ **未能核实**（本机 DNS 不通；CLI 文档 https://cli.dashlane.com/ 亦无法访问）；源码：产品闭源，CLI 开源 https://github.com/Dashlane/dashlane-cli ✅（Apache-2.0，230 stars，最近推送 2026-10-22，v6.2642.0，2026-10-13）。
- 简介：老牌商业密码管理器，特色内建 VPN（现拆分为 Plus 档）与暗网监控；近年重心转向企业，个人产品线仍在维护。
- 加密架构（安全白皮书 v2.0.3，2023-05-16，经英国 G-Cloud 镜像 PDF 全文提取核实）：个人数据客户端 AES-256 加密；对称密钥由 UserMP（主密码）+ UserSecondaryKey（32-byte 随机，本地生成）共同派生；KDF 为 **Argon2d**（或 PBKDF2-SHA2，历史公开口径 PBKDF2-SHA256 600,000 次后迁移）；主密码永不联网传输；服务端认证用独立 DeviceKey（40 字节）——认证密钥与数据加密密钥分离；共享走 RSA-2048 + 每条目一次性 ObjectKey（AES-CBC + HMAC-SHA2）；暗网监控 Argon2d v1.3 + K-anonymity（仅上传哈希前 3 字节）。
- 收费：官方 pricing 页动态渲染，个人档官方数字**未能直接核实**；第三方评测（2025–2026 多方一致）：Free（限 25 条/1 设备）、Premium **$4.99/月**、Friends & Family **$7.49/月**（最多 10 人）——标注为「第三方来源，官网未直接核实」。
- 安全审计：无公开完整审计报告列表页（Trust Center 需登录）；第三方汇总称委托过 ISE 等机构并持 SOC 2 Type II、ISO 27001；MIT 6.857 课程分析（2016）；白皮书公开可查是主要依据。**标注：官方公开审计报告不如 1Password/Proton Pass 充分。**
- 优点：白皮书技术披露详实（Argon2、密钥分离、SSO 密钥流）；CLI 开源活跃；内建 VPN/暗网监控。缺点：**Linux 无桌面应用**（仅网页版+CLI）；❌F6；个人档价格透明度一般；F8 未见官方等价 `op run` 的注入包装命令（cli.dashlane.com 本机不可达，未能逐条核对）。
- F 对照：F1✅ F2✅ F3✅（零知识 + DeviceKey 认证分离）F4❌（无密钥文件；UserSecondaryKey 由服务端参与分发）F5⚠️ F6❌ F7✅ F8⚠️ F9✅/⚠️（应用内 CSV 与主流管理器导入；无环境变量扫描）F10⚠️（CSV/JSON 明文导出；无加密归档选项）。
- 适用场景：Windows/macOS 为主、看重暗网监控与 SSO 集成的个人/企业；对本项目参考价值主要是其白皮书的 KDF 与密钥分离论述。

### 2.4 LastPass（反面教材）

- 三件套：官网 https://www.lastpass.com/ ✅（2026-10-25 curl 200）；官方文档 https://support.lastpass.com/ ✅；源码：产品闭源，官方 CLI 开源 https://github.com/lastpass/lastpass-cli ✅（GPL-2.0，2911 stars，最近推送 2026-10-19）。
- 简介：老牌 SaaS 密码管理器，2021–2023 事件链后信任修复缓慢，仅剩存量企业与"图省事"用户。
- 加密架构：保险库 blob 客户端 AES-256 加密上传；主密码经 **PBKDF2** 派生（默认迭代长期为 **100,100**，远低于同期 OWASP 建议的 600,000；事后部分账户提升至 150,000，新账户再提升至 600,000）；关键缺陷：**blob 内网站 URL、条目标题等字段为明文/弱混淆**（2022-12 官方公告原文承认 "unencrypted data, such as website URLs"）；无类似 1Password Secret Key 的第二因子。
- 收费：页面正文动态占位符渲染无法直读；页面 meta 描述给出 "Premium starts at $2.25/mo"（官方页面数据）；档位：Free（限一种设备类型）/ Premium（1GB 存储）/ Plus / Families / Teams / Business / Business Max。
- 安全事件：详见第 4 节横向核实——2021 开发环境失窃（源代码+技术信息）→ 2022-08 再次入侵 → 2022-11-30 第三方云存储异常 → 2022-12-22 官方确认保险库备份被复制 → 2023-02/03 承认攻击者已获得解密云存储所需员工凭据与密钥。2022-12-22 公告已核实（WebFetch 全文提取）；2021-09 与 2023-02/03 公告原帖被 Akamai 拦截（403/404）未能直接核实原文，事件链经官方公告回溯表述与多方报道交叉印证。
- 架构缺陷分析（反面教材五条）：① 混淆而非真正字段级加密（URL/标题明文，泄露即暴露上网画像）；② KDF 迭代过低且长期不升级（弱主密码面临现实可行离线爆破）；③ 无第二因子（主密码强度=保险库强度）；④ 开发/生产凭据隔离不足（纵深防御失败）；⑤ 危机沟通失信（"无客户影响"结论被后续披露推翻）。
- F 对照：F1✅ F2⚠️（字段级加密不完整）F3⚠️（明文字段+低迭代削弱实质）F4❌ F5✅（全平台覆盖）F6❌ F7✅/⚠️（lastpass-cli 陈旧）F8❌（`lpass show` 仅可脚本取值，无注入包装）F9✅（CSV 导入成熟）F10⚠️（CSV 导出，无加密归档）。
- 适用结论：不推荐。对本项目的价值是**反面规范**——字段级全加密、强 KDF（≥600k PBKDF2 或 Argon2）并允许升级参数、不依赖服务端信任的第二因子（密钥文件）、开发/生产环境严格隔离，四条底线缺一不可。

### 2.5 Enpass

- 三件套：官网 https://www.enpass.io/ ⚠️ 部分可达（curl 浏览器 UA 首页 403 反爬，/pricing/ 与 /release-notes/ 等子页 200；WebFetch 均被 403 拦截，定价经 curl 抓 HTML 提取）；官方文档 https://support.enpass.io/ → 301 → https://help.enpass.io/ ✅（同步机制文档 vault-management 页实测可达）；源码：无（客户端闭源）。
- 简介：「本地优先」密码管理器——**没有任何 Enpass 自有服务器**；保险库 = 一个加密数据库文件，同步完全走用户自己的云盘或局域网。官方明确："Enpass 在你的所有设备间同步你的 vault，而不会向 Enpass 服务器发送任何数据"。与本项目「云盘同步」路线直接同构，是本组内唯一不依赖厂商云的产品。
- 同步机制（官方帮助核实）：三种方式——① 用户自选云账户在线同步（**Dropbox、Google Drive、OneDrive、iCloud、Box、WebDAV、Nextcloud**）；② **Wi-Fi 同步**（完全离线）；③ **Folder Sync**（本地/挂载文件夹）。云盘上只有整库加密文件（密文）；首库为 Primary vault（其主密码解锁全部库），其余库各有独立密码。
- 收费（/pricing/ HTML 直提）：Free 最多 25 条/1 保险库；Premium $1.99/月（年付），3 年方案 $49.99，**Lifetime 买断 $99.99**（一次性）；Family $3.99/月（6 人）。**一次性买断是五者中唯一仍在售的永久授权**，对国内用户支付门槛最低。
- 版本：桌面版处于 6.11–6.12 区间（macOS Beta 6.12.7，2026-09-22）；未固定精确稳定版号，不作断言。
- 安全审计：早年曾公布外部安全评估结论，当前官网无完整公开审计报告列表；闭源 + 审计公开度有限是主要短板。标注：**未能核实近年独立审计**。
- 优点：唯一无服务器依赖；一次性买断；全平台含 Linux；数据主权完全在用户（F2/F3/F6 天然满足）。缺点：闭源；❌F7/F8 无 CLI 与注入能力；无网页端与实时协作；同步冲突处理依赖云盘文件语义。
- F 对照：F1✅（浏览器扩展+移动端填充）F2✅（本地加密数据库，主密码永不离开设备）F3✅（云盘由用户自选）F4⚠️（主密码不上云满足；无独立密钥文件机制）F5✅ F6✅（无服务器形态天然满足）F7❌ F8❌ F9⚠️（文件导入 CSV/JSON 十余种来源；无脚本/环境变量扫描）F10⚠️（CSV/JSON 明文导出；本地加密备份 .enpassbak 类；无加密归档导出）。
- 适用场景：隐私敏感、多设备个人用户；**对本项目 F2/F3/F6 + 云盘同步路线是最直接的商业先例**——「本地加密数据库 + 用户自选云盘同步密文文件」是被商业产品验证 10 年的可行路线；其缺失面（无 CLI、无冲突处理、闭源）正是自研可补足方向。

### 2.6 Bitwarden（官方 SaaS + 官方自部署）

- 三件套：官网 https://bitwarden.com/ ✅；官方文档 https://bitwarden.com/help/ ✅；源码 https://github.com/bitwarden ✅（server、clients、android、ios 等 69 个仓库全栈开源）。关键子页（均实测）：定价 /pricing/、CLI /help/cli/、安全白皮书 /help/bitwarden-security-white-paper/、自部署 /help/hosting/、Lite /help/install-and-deploy-lite/、审计页 /help/is-bitwarden-audited/、1Password 导入 /help/import-from-1password/。
- 简介：最主流的开源密码管理器之一（GPL/AGPL 系），客户端（网页、扩展、桌面、移动、CLI）与服务端全部开源，零知识端到端加密；商业形态为云端 SaaS、官方自部署（标准版 + Lite）、Secrets Manager（开发者密钥管理）。
- 加密架构（白皮书核实）：零知识——主密码"从不经互联网传输到 Bitwarden 服务器"，Master Key/Stretched Master Key 从不上传；服务器只存密文与二次加盐哈希。KDF：默认 PBKDF2-SHA256 **600,000 次**（邮箱作盐）；可切换 **Argon2id**（默认参数 memory 32 MiB / iterations 6 / parallelism 4，上限 1024 MiB/1024/16；社区加固建议最慢解锁设备约 1 秒解锁）。算法：AES-256-CBC + HMAC-SHA256（Encrypt-then-MAC），每条 Cipher 独立 64 字节密钥；组织共享走 RSA-OAEP；HKDF 拉伸至 512 位 Stretched Master Key。传输/存储：TLS+HSTS；Azure TDE + 列级加密。**F3 完全满足，白皮书明确服务器无明文还原能力。**
- 收费（pricing 页核实）：Free $0（**条目数无上限**，可与 1 人共享；2FA 仅验证器 App/邮件）；Premium $1.65/月（解锁条目内 TOTP 生成器、加密附件 1GB、健康报告、YubiKey/Duo/FIDO2——**TOTP 生成器是 Premium 功能，免费档不可用，对 F8/开发场景是隐藏收费点**）；Families $3.99/月（6 人）；Teams $4/月/用户；Enterprise $6/月/用户。
- 自部署（F6）：标准版最低 x64 双核 2GHz / **2GB RAM** / 12GB 盘（推荐 4GB/25GB），Docker Engine 26+，开放 80/443，自带 MSSQL Express（10GB 上限），需到 bitwarden.com/host 领安装 ID/密钥；**Lite（原 Unified，2025-12 从 Beta 毕业）最低 200MB RAM / 1GB 盘**、支持 ARM（树莓派/NAS）、单镜像 `ghcr.io/bitwarden/lite`、数据库自备（SQL Server/PostgreSQL/SQLite/MySQL），仅面向个人/homelab（官方明确不用于商业场景）。自部署免费，但 SSO/Key Connector/企业策略等企业功能仍需付费订阅；安装时需联网领取安装密钥（离线部署除外）。
- CLI（`bw`，TypeScript/Node）：`bw unlock` 生成 session key（`export BW_SESSION=<session-key>`，仅存环境变量不落盘，`bw lock`/`bw logout` 失效；2026.9+ 桌面端支持生物识别解锁 IPC）；`bw get item/username/password/totp/uri/attachment`（`--raw` 裸文本 stdout）。**重要核实结论：当前版 CLI 已无 `bw run`**——官方帮助页与开源仓库命令注册（vault.program.ts、register-oss-programs.ts 等）核查，现存子命令 list/get/create/edit/delete/restore/confirm/import/export/encode/status/serve 等，**不存在 run**；历史版基于 JSON 配置的 `bw run` 已被移除且无文档，旧脚本在新版 `@bitwarden/cli`（2026.10.0）上不可用。
- F8 结论：bw 没有与 `op run --` 等价的原生临时注入命令。社区惯用命令替换方案的风险：`$(bw get ...)` 展开结果**进入外层 shell 命令行/子进程参数**，可能被 `ps -ef`、shell history、CI 日志捕获；秘密在 shell 变量存留到脚本结束无自动清除；`bw serve`（本地 REST API）把明文暴露在本地端口。需要严格 F8 语义时应改用 **BSM 的 `bws run`**。
- 导入/导出（F9/F10）：`bw import <format> <path>`（`--formats` 列全格式，含 bitwardencsv/lastpasscsv/**1password1pux**/1passwordpif 等）；`bw export --format json|encrypted_json|csv|zip`——**zip 连同附件一起导出**（CLI 文档核实）；encrypted_json 用账户密钥或 `--password` 二次加密。加密归档 F10 基本满足，但"附件+加密 JSON"无法一步合成单一归档（附件单独在 zip 里）。
- 安全审计：2018 起持续第三方审计；2023 Cure53；2024 Cure53、Mandiant、IOActive、Paragon、Fracture Labs；**2025 年密集审计——Cure53（扩展/自动填充浮层/核心应用/桌面/RustCrypto/Web Vault）+ ETH Zurich 应用密码学小组（假设服务器完全恶意的核心密码学操作）+ Unit 42（移动端）+ Fracture Labs（Web 与网络组件）**，报告 PDF 公开；SOC 2 Type 2、ISO 27001、HackerOne。
- CVE 与供应链：网传 "CVE-2023-24044/43140" **均不是 Bitwarden**（NVD 全量检索，24044 实为 Plesk Obsidian）；真实相关记录：CVE-2018-25081（跨域 iframe 自动填充，设计争议）、CVE-2023-27974（二级域名匹配填充）、CVE-2023-27706（桌面生物识别密钥存本机凭据管理器）、CVE-2023-38840（本地内存信息泄露）；**CVE-2026-42994 npm 渠道投毒事件**（见第 4 节）；2025–2026 官方 Server 多个访问控制类 CVE（CVE-2026-43638/43639/43640、57520/57521/57522、60104 等），需及时跟版。
- 自部署安全注意事项：必须 HTTPS（Web Vault 依赖 secure context Web Crypto）；反向代理收口仅暴露 80/443；SMTP 配置正确否则重置邮件外泄；定期备份 database+attachments+keys（标准版）/ /data 卷（Lite）；锁定管理端口；服务器主机即"所有密文保险库"持有者，主机沦陷=离线爆破主密码，KDF 应调高。
- F 对照：F1✅（第一梯队）F2✅ F3✅ F4⚠️（主密码不上云 ✅，但无 KeePass 式独立密钥文件）F5✅ F6✅（标准 2GB / Lite 200MB 双路线）F7✅ F8❌（无原生注入；BSM 除外）F9✅（CLI/GUI 多格式含 .1pux）F10⚠️（加密+附件可达成，无"单一加密全量归档"一步命令）。
- 特色：Bitwarden Send（阅后即焚）、紧急访问、FIDO2/passkey、SSH 代理（新）、Directory Connector（仅 AD/LDAP/GSuite/Entra ID 用户组同步，不迁移密码条目）。
- 优点/缺点：全栈开源、零知识被 ETH Zurich 恶意服务器审计背书、免费条目不限量、自部署双形态弹性大、导入格式生态最全；反之 TOTP/附件属 Premium、CLI 无安全注入原语、标准版偏重（MSSQL）、Server 近年 CVE 频出跟版压力大。
- 适用场景：想要"1Password 全功能 + 可自托管"的个人/小团队；对厂商信任要求高又要保留 SaaS 便利的混合场景。

**2.6.1 Bitwarden Secrets Manager（BSM，附属核实）**：面向开发者/DevOps 的基础设施密钥（API key、连接串、证书）管理，与 Password Manager 并列；核心对象 Secrets/Projects/Machine Accounts/Access Tokens。三件套：https://bitwarden.com/products/secrets-manager/ ✅、CLI 文档 https://bitwarden.com/help/secrets-manager-cli/ ✅、SDK https://github.com/bitwarden/sdk-sm ✅。免费档 2 用户/3 项目/3 机器账户、secret 不限量；自托管概述页写 "can also be self-hosted" 但套餐页标 "Enterprise, coming soon"——**两页口径不一致，采用前需实测**。`bws run -- 'npm run start'` 以 Access Token 拉取项目 secrets 注入子进程（`--project-id`、`--shell`、`--no-inherit-env`、`--uuids-as-keynames`；state 文件默认 `~/.config/bws/state`，加密存储认证令牌并跨运行复用）。**`bws run` 是 Bitwarden 体系内最接近 `op run` 的原生实现，也是自研 F8 最佳参照（含 POSIX 兼容细节与 state 加密设计）**；但作用域是机器密钥，个人密码条目仍无 `bw run`。

### 2.7 Vaultwarden（第三方 Rust 服务端）

- 三件套：主页/仓库 https://github.com/dani-garcia/vaultwarden ✅（经 GitHub API 与页面双重核实）；文档 Wiki https://github.com/dani-garcia/vaultwarden/wiki ✅（66 页，2026-10-06 仍更新）；源码同仓库（AGPL-3.0，69,616 stars，最近 push 2026-10-22）。
- 简介：Bitwarden Client API 的**非官方**替代服务端实现（Rust，原名 bitwarden_rs，2021 年 v1.21.0 起更名切割商标）；与官方客户端（扩展/桌面/移动）直接兼容，为"官方服务端太重"的自部署场景而生。README 注明：**一位现任维护者受雇于 Bitwarden**（以个人时间贡献、经其他维护者评审）；项目与 Bitwarden 官方无隶属关系。
- 免责声明要点（README 核实）：与 Bitwarden/Bitwarden Inc. 无关联；出 bug 报 Vaultwarden 而非官方支持渠道；**维护者不对使用 Vaultwarden 造成的任何数据丢失（密码、附件等）负责**，强烈建议定期备份文件与数据库。官方 Wiki 明确缺失功能：公共 API 仅部分支持、Passkey 登录、新设备登录保护、自定义角色及部分企业策略不支持。
- 功能覆盖：个人/组织保险库、Collections、共享、事件日志、Admin Password Reset、Directory Connector、策略、Send、附件、网站图标、个人 API Key、紧急访问、2FA（TOTP/邮件/FIDO2/YubiKey/Duo）、自带管理后台与改版 Web Vault（`bw_web_builds` 打包进容器）。
- 资源需求：不发布正式最低配置（社区定位"能跑在树莓派上"）；实测社区数据：空闲约 10–30MB RAM，生产典型 400–500MB；Pi Zero 2 W（512MB）可用；**源码编译需约 7GB RAM**（低配机用预构建 Docker 镜像，ghcr.io/docker.io/quay.io 三渠道）。对比：官方 Lite 已降到 200MB——资源优势缩小，剩余优势是免安装密钥、单 SQLite 文件、默认解锁全部 Premium 类功能（社区公知行为，非官方承诺）、配置极简。
- 安全性：CVE 流水明显高于官方 Server（详见第 4 节：2024–2026 连续多轮授权逻辑/组织边界类缺陷——客户端加密不受影响，密文仍安全，但服务端实现质量需以"高频打补丁、依赖自己及时升级"假设运营）。威胁模型分析："厂商投毒"下自部署解决**服务端**投毒；残余包括客户端二进制仍来自官方渠道、信任链变为"维护者+分发镜像"（ghcr.io 构建流程开源可复核）、自部署网页端页面由服务端推送（服务端投毒可直接投 JS，用扩展/桌面客户端可收窄）。
- F 对照：F1/F2/F3/F5 同官方客户端 ✅；F4⚠️（无 keyfile）；F6✅（数百 MB RAM 级）；F7✅（`bw config server <你的自部署地址>` 即可指向）；F8❌（另注意不支持完整公共 API，`bw serve` 受限）；F9✅；F10⚠️（无官方技术支持兜底，备份自建自担风险）。
- 优点：极轻量、部署/备份极简、免费获官方 Premium 档体验、社区极活跃（7 万 stars、月度 release，最新 1.37.4，2026-10-05）。缺点：非官方、无审计背书、不对数据丢失负责、CVE 频出需自觉跟版、缺 Passkey 登录/新设备保护/完整 API、改版 Web Vault 引入额外信任环节。
- 适用场景：个人/homelab/极小团队，把"自主可控+低资源"放在"官方审计背书"之前；不适合有合规要求的企业。

### 2.8 KeePass 生态（KeePassXC 为代表 + 客户端群）

- 三件套（KeePassXC）：官网 https://keepassxc.org/ ✅；文档 https://keepassxc.org/docs/ ✅（含 FAQ 与 UserGuide https://keepassxc.org/docs/KeePassXC_UserGuide.html ✅）；源码 https://github.com/keepassxreboot/keepassxc ✅（GPLv3）。最新版 **2.8.0**（2026-10-21，Qt5→Qt6、Wayland Auto-Type、"remote sync with external tools"）；上一稳定 2.7.12。完全免费。
- 其他成员（均核实）：
  - **KeePass 2.x 原版**：https://keepass.info/ ✅，2.61.1（2026-05-01），GPL 类开源全免费；KDBX 4 规范定义者（AES-256/ChaCha20/Twofish + AES-KDF/Argon2（2.48+ 支持 Argon2id）+ KDBX4 强制 HMAC-SHA-256 头部认证 + 每块 Encrypt-then-MAC；附件移入加密内部头）；支持"从文件/URL 打开与同步"（官方 trigger 示例含 Dropbox/网盘触发器与 Box.com WebDAV 触发器；冲突时保留最新修改时间，旧变更入条目历史不丢数据）；CLI 靠官方 KPScript 工具（无 `op run` 等价注入）。
  - **KeePassDX（Android）4.5.6**（2026-10-17，https://github.com/Kunzisoft/KeePassDX ✅，GPLv3）：KDBX 1–4 读写、TOTP/HOTP、系统级 Autofill + Magikeyboard、生物识别、Passkey 本地存储；**不内置任何 WebDAV/云 API**（设计哲学："密码编辑器不该负责云同步"），文件访问全部委托 Android SAF——经 RCX/RSAF（rclone）可挂坚果云 WebDAV；**官方 Wiki 明确警示 Google Drive（链接过期/延迟保存/丢数据）与 OneDrive（URI 重分配、>512KiB 文件损坏）不要用于 KDBX**；Syncthing 可用但警告避免并发保存（损坏风险）；数据合并靠 Save/Merge/Reload/**Merge from…**。

  - **KeePassium（iOS/macOS，开源）**：https://keepassium.com/ ✅（GPLv3）；**WebDAV 直连完整支持**（Nextcloud/ownCloud/Synology/QNAP/通用）；OneDrive/Google Drive/Dropbox 直连 API + Files app 双路完整支持；iCloud Drive/SMB/Box/pCloud/Seafile 完整支持；免费版仅 1 个数据库（含 OTP/Face ID/系统 AutoFill）；Premium €19.99/年（rent-to-own）；Pro €79.99 买断；官网宣称"唯一经过独立安全审计的 KeePass 兼容移动应用"。
- 模型：**KDBX 单个加密数据库文件 + 任意云盘同步**是 KeePass 生态原生形态——云端只见密文（F3 天然满足），无服务器（F6 天然满足），零订阅费。多设备并发写冲突由 **KDBX 条目级合并机制**兜底（条目有 UUID、逐字段修改时间与删除历史；合并按"新者胜 + 旧版本入 history"，两端同时编辑不同条目合并后都不丢），前提是各端使用支持合并的客户端、不让云盘"整文件覆盖"。
- KDF（KeePassXC，UserGuide 核实）：数据库设置→安全→高级可选 AES-KDF 或 **Argon2**（Argon2d 最大兼容 / **Argon2id 抗时序攻击，推荐**），参数为内存/迭代/并行度 + "解密时间"滑杆（官方建议 1 秒）；完整支持 KDBX 4.1。
- 浏览器自动填充（F1）：**KeePassXC-Browser** 扩展（Firefox/Chrome/Edge），架构为浏览器 → `keepassxc-proxy`（native messaging）→ Unix socket/命名管道 → KeePassXC 本体；协议文档公开；凭据不落浏览器存储。SSH Agent 集成内置（解锁后自动加载密钥进 ssh-agent）。
- CLI（F7）：`keepassxc-cli`——`show`（-a/-t/--show-attachments/-s）、`clip`（超时自动清剪贴板）、`export -f xml|csv`（默认 XML）、`import <xml>`（仅 XML→新建 kdbx4）、`merge [-s] [--dry-run]`、add/edit/ls/mv/rm/mkdir、`attachment-export/--stdout`、`analyze`（离线 HIBP）。**F8 结论：没有 `op run` 式子进程注入命令**；社区通行 shell 包装或 direnv 组合（非官方功能）。
- 导入导出（F9/F10）：GUI 支持 CSV/XML/HTML 导出与多格式导入（CSV、1Password、KeePass 1.x/2.x XML 等）；CLI 仅 XML 导入；KDBX 3.1/4 原生、KDBX 2 自动升级、.kdb 可导入不可导出。KeeShare 组间共享：按组 Inactive/Import/Export/Synchronize 四模式，签名分享容器；**签名只验签发者、无法检测回滚到旧版本**——不是全库同步方案。
- 云盘同步立场：官方 FAQ 明确**不内置云同步**，建议数据库文件放云盘同步目录；**KeePassXC 不支持直接打开 WebDAV URL**（KeePass 2.x 支持 URL 同步）。
- 审计：官方审计页（keepassxc.org/audits/ ✅）列出 **ANSSI Security Visa ANSSI-CSPN-2025/16**（法国国家网络安全局认证流程，Synacktiv 执行，覆盖 2.7.9/Windows 10，2025-11-17 至 2028-11-17 有效）与 Molotnikov 源码审查（2023-01，2.7.4）。KeePass 原版无同级别现代第三方审计记录，但经 20+ 年公开检验。
- F 对照（KeePassXC 为代表）：F1✅（桌面最佳；KeePass 原版浏览器生态基本停摆，KeeFox 已停更）F2✅ F3✅ F4✅（keyfile+主密码组合；**密钥文件勿与库同盘目录**）F5✅ 桌面（无移动端，靠 KeePassDX/Strongbox/KeePassium 补齐）F6✅ F7✅ F8❌ F9✅ GUI 多格式 F10✅（KDBX 即全量加密导出）。
- 移动端 F1 体验差距：KeePassDX/Strongbox/KeePassium 依赖系统 AutoFill 框架，字段匹配精度弱于 1Password 专有引擎；Strongbox/KeePassium 的高级匹配属付费项。
- 适用场景：零服务器、软件费为 0 的路线主力（对照 1Password 约 $36–60/人/年订阅）；唯一硬缺口是 F8，需 shell 包装凑合或 CLI 重度场景补 gopass。

### 2.9 pass / gopass

- 三件套：官网 https://www.gopass.pw/ ✅（pass 官网 https://www.passwordstore.org/ ✅）；文档 https://github.com/gopasspw/gopass/tree/master/docs ✅（`gopass env` 文档 docs/commands/env.md 经 GitHub 核实）；源码 https://github.com/gopasspw/gopass ✅（MIT）。最新 v1.17.4（2026-10-10）。
- 模型：每条密码 = 一个 GPG 加密文件（`~/.password-store` 目录树），**git 做版本控制与同步**（`gopass git push/pull`），GPG 做端到端加密；pass（bash 原版）是同一哲学鼻祖，gopass 是 Go 重写+增强。同步：git 托管（GitHub/GitLab private repo 即满足 F3）或任何能同步 git 裸仓库的盘；冲突由 git 合并处理（更精细），但移动端体验弱（Android 有 Android-Password-Store，iOS passforios）。
- **F8 亮点——`gopass env <密钥子树前缀> <命令>`**（官方文档核实存在）：把该前缀下每个密钥导出为大写环境变量后**以子进程运行命令**（如 `gopass env db/prod psql ...`），语义等价 1Password `op run`。变体：`--stdin`（改走 stdin，规避 `/proc/<pid>/environ`、`ps eww` 泄露路径，官方推荐）、`--file`（写 ramdisk 临时文件并导出 `<KEY>_FILE` 路径，学 12-factor）、`--exec`（exec 替换进程，**Windows 不可用**）、`--keep-case`。**这是 KeePassXC CLI 缺失、且用户需求点名的 F8 能力。**
- 导入（F9）：无跨密码管理器批量导入命令；`gopass convert` 仅后端迁移（storage+crypto 组合，如 gpg→age）；`gopass copy/move` 库内/挂载点间复制。实际迁移桥是第三方 **pass-import**（https://github.com/roddhjav/pass-import ，GPL-3.0，915★，最后提交 2026-06）：支持 1Password/Bitwarden/KeePass 家族/LastPass 等 40+ 来源，目标端明确支持 gopass。
- F 对照：F1❌（无 GUI；passff/browserpass 可浏览器填充）F2✅（GPG 端到端）F3✅（git 上只有 GPG 密文）F4✅（GPG 私钥本地；无主密码概念）F5✅（Win/macOS/Linux；移动端生态弱）F6✅（git 服务器可自建）F7✅✅（原生即 CLI）F8✅ F9⚠️ F10✅（目录即明文/密文文件树）。
- 适用场景：CLI 重度开发者的密钥管理；与 KDBX 库并存分工（服务凭据走 gopass+git private repo，个人密码走 KDBX+云盘）。

### 2.10 Infisical

- 三件套：官网 https://infisical.com ✅；官方文档 https://infisical.com/docs/documentation/getting-started/cli ✅、CLI 参考 https://infisical.com/docs/cli/reference ✅、自托管 https://infisical.com/docs/self-hosting/deployment-options/docker-compose ✅；源码 https://github.com/Infisical/infisical ✅（30k stars，**MIT 核心 + 企业版目录 ee 另授权**）。平台最新 release v0.167.2（2026-10-23，GitHub API 核实）。
- 简介：开源密钥管理平台（服务端集中管理 + CLI 注入），管理 API key、数据库凭证、证书——**不是个人密码管理器**（无浏览器自动填充，不做登录密码/身份管理）。
- 加密与信任模型：**服务端加密模型，非零知识（如实标注）**——密钥明文在服务端内存中用于加解密，用户/CLI 经 TLS 取回解密后的值；KMS 表述印证："Keep cryptographic keys in Infisical instead of in your applications"。自托管实例用 `.env` 里的 **`ENCRYPTION_KEY`**（根密钥，加密全部数据，丢失即不可恢复）；静态加密 AES-256-GCM，传输 TLS 1.2+，企业档 FIPS 140-3 模式。**含义：服务器被攻破 + ENCRYPTION_KEY 泄露 = 全部密钥泄露**——与 1Password/Bitwarden 的零知识是不同信任模型。
- 收费（/pricing 核实）：云 Free $0（5 身份、3 环境、无 RBAC/SSO/轮换）；Pro $20/身份/月（年付，月付 $23）；Advanced $40；Enterprise 定制（SSO/SCIM/审计流/KMIP/HSM、99.99% SLA）；PAM $20/用户/月起。自托管 MIT 核心永久免费（SSO 强制/LDAP/SCIM/KMIP/HSM/审计日志流/RBAC 属付费授权）；对个人/小团队场景（密钥管理+CLI 注入）MIT 版完全够用。
- 自托管：Docker Compose 三容器（backend Node/TS+Go + PostgreSQL（存加密后密钥，pg_data 是唯一真相源）+ Redis），可选 nginx HTTPS；**官方资源需求 CPU 2/4 核、内存 4/8GB、盘 20/50GB（SSD）**；另支持 Kubernetes(Helm)/Linux 包/气隙部署（气隙属企业档）。升级运维：备份 PostgreSQL 卷与 `ENCRYPTION_KEY`；PG 5432/Redis 6379 不得暴露公网。
- CLI 与 F8：`infisical run --env=dev -- npm run dev`（CLI ≥0.43.145 也可 `infisical sm run`）——语义与 `op run` 同族：进程级注入、`--` 后接命令；注入值覆盖 shell 同名变量但 `HOME/PATH/USER/TERM/SHELL/XDG_*/LC_*` 等系统关键变量**永不注入**；`--path`（按文件夹）、`--recursive`、`--watch`（服务端密钥变更自动重启）、`--print`。认证：交互 `infisical login`（浏览器 OAuth），无人值守 Machine Identity 的 `INFISICAL_TOKEN`；登录态/token 保存在 `~/.infisical`（**磁盘凭证缓存，非密钥明文缓存**——密钥每次经 TLS 拉取解密到内存注入）。`infisical secrets export --format=dotenv` 是"拉取落盘"模式（官方警告明文落盘易过期）。**Windows 一等公民**：winget/Scoop/npm，文档含 PowerShell/cmd 示例，Git Bash 下 `infisical run -- printenv <KEY>` 可用。CI：`INFISICAL_TOKEN` + `infisical run` 一行接入。
- 导入导出（F9/F10）：**不存在 `infisical import` 命令**（CLI 参考核实）；导入 .env/.yaml 靠 `infisical secrets set --file <路径>`（一次一个文件，无目录扫描、无跨文件去重）；平台侧 external migrations（Doppler/Vault）与 secret syncs（1Password/Vercel/AWS Secrets Manager 等 40+ 目标双向同步）是"平台对平台同步"，非 CLI 批量导入。`secrets export`（.env/JSON/stdout）覆盖 F10。
- 安全审计：SOC 2 Type II、HIPAA、GDPR 合规（官网宣称）；**未见公开的第三方代码审计报告**；无重大公开 CVE 记录（本调研范围内）。
- F 对照：F1❌ F2❌（加解密在服务端）F3⚠️（云版存密文但服务端持钥）F4❌ F5✅ F6✅（4GB 内存起）F7✅ F8✅✅ F9⚠️ F10✅。
- 适用场景：自己服务器上"今天就可用"的 F6+F7+F8 成品（接受服务端持钥模型）；Web UI 弥补无 F1 短板；版本迭代快需跟升级。

### 2.11 Vault / OpenBao

- 三件套：Vault https://developer.hashicorp.com/vault ✅（原 vaultproject.io 308 重定向）、Agent 文档 https://developer.hashicorp.com/vault/docs/agent-and-proxy/agent ✅、https://github.com/hashicorp/vault ✅；OpenBao https://openbao.org ✅、https://openbao.org/docs/install/ ✅、Process Supervisor 文档 https://openbao.org/docs/agent-and-proxy/agent/process-supervisor ✅、https://github.com/openbao/openbao ✅（8.7k stars，MPL-2.0）。
- 简介：企业级机密管理/加密即服务（KMS 动态密钥、Transit 引擎、PKI）；CLI + Agent 双形态。OpenBao 是 Vault 的社区 fork（Linux Foundation / OpenSSF 治理），fork 自 Vault 1.14（最后的 MPL 版本），支持 Vault CE 1.14.x 原地迁移并有意保持 API 兼容。
- 许可变更史（Vault）：自始至终 MPL 2.0 直至 **2023-08-10** HashiCorp 宣布全线改 **BUSL 1.1**（源码可用、4 年后逐版本转回 MPL、禁竞争性商业产品）；首个 BUSL 版本 1.15.0（2023-10）；**≤1.14.x 保持 MPL 2.0**。BUSL 允许内部生产使用（自部署不付费不违法），但非 OSI 开源、不能做竞争性商业服务、部分高级功能（HSM/DR/Namespaces）仍锁企业版；2025 年 IBM 收购 HashiCorp 后社区疑虑加深——即 OpenBao 诞生的土壤。
- 注入（F8）：**无一键 `run` 命令**。`vault|bao kv get -field=password secret/foo` + shell 导出是 shell 级注入（"临时性"最弱：留在当前 shell 需手动 unset，写脚本易进 history）。进程级注入须走 **Agent `env_template` + Process Supervisor Mode**：Agent 以 exec 启动子进程、渲染结果作为环境变量注入、子进程退出环境消失、与文件模板互斥、设计上不写明文文件；静态密钥按 `static_secret_render_interval` 刷新，`restart_on_secret_changes = "always"` 时密钥变更重启子进程。OpenBao `bao agent` 同功能（**public beta**），`bao agent generate-config -type="env-template"` 辅助生成；社区 issue #4110 请求内联命令语法尚未实现。任务背景中提到的 "baob" 命令**不存在**（文档与仓库均无）。
- 加密与信任模型：服务端持钥 + **Shamir 封装冷启动保护**——启动后 sealed，存储后端数据永远是密文，unseal 需 Shamir 密钥分片（N-of-M）或 auto-unseal（云 KMS/HSM/PKCS#11，OpenBao 2.7 起插件化）；主密钥不落盘只在内存用于 barrier。Transit 引擎=加密即服务（应用永远拿不到密钥）。对比 Infisical：信任模型相同（服务端持钥），但多了"密封"冷启动保护。
- 收费：Vault 社区版（BUSL）免费自部署；HCP Vault Dedicated Dev 档约 $0.03/小时（约 $22/月），生产档约 $1.58–$9.41/小时（约 $1,150–$6,900/月，**第三方向 2026 估价**，官方按规格/区域浮动）；企业授权未公开价。OpenBao 无云版、完全免费（MPL 2.0）。
- 平台与运维：Vault 单二进制+存储后端（文件/Consul/PG 等），生产需考虑 unseal/TLS/audit device；Windows 官方支持（含 "Run Vault Agent as a Windows service" 文档）；OpenBao 官方 Docker 镜像（Alpine/UBI）、Helm、二进制、`bao.exe`，2.7.0 起 seal 插件化、PebbleDB 后端、后量子 TLS。
- 安全：Vault 1.9 由 **Kroll** 审计、更早由 ATSEC International 审计；2026 年多个策略解析类漏洞（HCSEC-2026-32 / CVE-2026-5006 模板策略路径斜杠注入→提权，2026-08-24 修复；CVE-2026-89322；cache-key collision 等，v2.2.1 修复）；ControlPlane 2026-09 披露 4 漏洞链可完全接管 Vault/OpenBao 服务器（补丁已发）。OpenBao：ControlPlane 研究；代码执行漏洞链（v2.6.3/2.7.0 修复）；信息泄露 CVE 影响 2.2.0–2.6.3 与 2.7.0（v2.6.4/v2.7.1 修复，2026-10-01，含 6 项 GHSA）。当前版本：Vault v2.2.1（2026-10-22）；OpenBao v2.7.1（2026-10-01）。
- F 对照：F1❌ F2❌（服务端加密）F3⚠️ F4⚠️（数据落自己的存储，unseal 密钥可离线保管）F5✅ F6✅（Vault 需读懂 BUSL；OpenBao 零焦虑）F7✅ F8⚠️（Agent 配置门槛高）F9✅（API/CLI 写入）F10✅（kv get/export）。
- 适用结论：对个人密码管理场景**过重**（unseal、策略、租约体系），仅在需要动态密钥/证书体系时考虑；"零许可焦虑"选 OpenBao；"自建在个人服务器 + Vault 能力"场景 OpenBao 是直接替代。

### 2.12 SOPS + age

- 三件套：SOPS https://getsops.io ✅（CNCF Sandbox，原 Mozilla 项目）、高级用法文档 https://getsops.io/docs/usage/advanced ✅、https://github.com/getsops/sops ✅（MPL-2.0，v3.13.3，2026-07-23）；age https://age-encryption.org ✅（302 重定向至 GitHub）、https://github.com/FiloSottile/age ✅（BSD-3-Clause，24.1k stars，v1.3.2 含后量子密钥支持）。
- 简介：SOPS 文件级加密工具（YAML/JSON/ENV/INI/二进制）——**只加密值**（键名、注释明文保留）；每文件数据密钥被各"接收者"（age 公钥、AWS/GCP/Azure KMS、PGP）分别加密，支持**密钥组 + Shamir 分片**（N-of-M 后端组合解密）；`.sops.yaml` 创建规则按路径选加密后端。age：极简文件加密格式（age-encryption.org/v1），X25519 密钥对（v1.3.0+ 可选 mlkem768x25519 后量子混合），零配置、可管道组合；另有 Rust 实现 rage、TS 实现 Typage。
- 信任模型：**无服务端、纯本地端到端**，密文随 git/云盘分发，私钥在你手里——最接近"密钥文件本地+主密钥不上云"（F4）的哲学，但没有团队共享 UI/审计。
- 注入（F8）：`sops exec-env <file> '<command>'`——"execute a command with decrypted values inserted into the environment"，进程级注入、明文不落盘、进程结束环境消失；`sops exec-file` 解密到临时文件，默认走 **FIFO（命名管道）不落盘**，FIFO 不可用时 `--no-fifo` 改为自动清理的临时文件——**官方明确把 Windows 列为 FIFO 不可用环境**。
- **Windows（用户主力环境，重点核实）**：SOPS 本体 `sops.exe` 支持 OK；`exec-env` 官方文档未明确声明 Windows 不可用，但命令以类 Unix shell 语义解析执行，`--user` 降权仅限类 Unix；GitHub issue 区存在 exec-env 特殊字符/多行值的多个平台相关 bug（#628、#784、#1127）——**在 Windows（含 Git Bash）上 exec-env 属"未获官方背书、实测易踩坑"**，可靠性显著低于 macOS/Linux；稳妥方案是 `sops decrypt --output-type dotenv` + 自行导入或 `exec-file --no-fifo`。age 在 Windows 支持良好（winget/Chocolatey/Scoop/官方二进制）。
- 密钥管理：age `age-keygen` 生成 `AGE-SECRET-KEY-1...`（v1.3.0+ 支持后量子混合 `AGE-SECRET-KEY-PQ-1...`）；私钥文件默认 `~/.config/sops/age/keys.txt`（**落盘，需自行保护**）。CI：`SOPS_AGE_KEY_FILE=<路径>`（或 `SOPS_AGE_KEY` 传私钥内容）+ exec-env/decrypt；GitOps 生态（Flux/Argo CD SOPS 插件）成熟。
- 安全：SOPS 仓库 Security 页记载已修复漏洞（exec-file/exec-env 切换用户时 UID 设为 GID，仅 Unix）——无重大公开 CVE；CNCF Sandbox。age 无公开商业审计报告（检索未发现 Cure53/ROS 报告）；格式有学术形式化分析（ProVerif/Tamarin 方向）；作者 Filippo Valsorda（前 Go 安全负责人）。
- F 对照：F1❌ F2✅（纯本地文件加解密）F3✅（密文文件可公开分发）F4✅（age 私钥文件本地+可加口令，无任何服务端）F5✅（exec-env Windows 受限）F6✅（无服务器天然"私有"）F7✅ F8⚠️（语义正确但 Windows 未背书）F9⚠️（需自己写脚本转换）F10✅（sops decrypt 即导出）。
- 适用场景：GitOps/文件级密文分发；其"只加密值、多接收者、Shamir 密钥组"的文件格式设计是自研 F2/F3/F4 最值得借鉴的架构；age 的 X25519 密钥模型值得作为自研底层原语。

**③ 私有部署自建服务器（F6 优先）**：要官方审计背书 + 可能商用/合规 → **Bitwarden 官方自部署**（小内存设备用 Lite 200MB RAM，正式营业环境用标准版 2GB RAM+；付出资源与运维复杂度，换来审计背书与官方安全响应）；个人/homelab 极低资源 + 想免费拿 Premium 档体验 → **Vaultwarden**（但必须接受非官方、无审计、不对数据丢失负责的免责框架，把及时升级+定期备份+fail2ban/HTTPS 加固当默认运维成本；其 2024–2026 CVE 密度表明这层风险真实）；想要开发者密钥平台 → **Infisical**（MIT，4GB RAM 起，接受服务端持钥）；需要动态密钥/PKI/KMS → **OpenBao**（MPL 2.0 零许可焦虑，Vault CE 1.14 原地迁移）。

**④ 零服务器云盘同步（F3/F4 + 国内云盘）**：首选 **KeePassXC（桌面）+ KeePassDX（Android）+ KeePassium/Strongbox（iOS）+ 坚果云 WebDAV** 管道（组合详见第 5 节；坚果云免费额度对单 KDBX 月消耗 MB 级绰绰有余）；CLI 缺口用 **gopass** 补 F8（可与 KDBX 库并存分工）；**Enpass**（$99.99 买断）是同构的闭源商业备选（唯一在售永久授权、支付门槛最低）。该路线 F2/F3/F4/F6 满分、软件费 0，代价是 F8 硬缺口与冲突纪律（全端用支持合并的客户端）。

## 4. 安全性横向核实摘要（取自分报告 F）

核实方法：官方公告、NVD/CVE/GitHub Advisory API 实测查询、可靠安全媒体交叉验证；"已证实"=官方/权威一手来源可确认；网传说法经 API 实测证伪的单独注明。

- **LastPass 事件链（已证实）**：2021-08 攻击者进入开发者环境窃取部分源代码与专有技术信息 → 2022-08-25 披露第二波入侵 → 2022-11-30 攻击者利用窃得信息（含云备份加密密钥副本）进入第三方云存储**下载客户保险库备份** → 2022-12-22 官方公告确认（保险库内 URL 明文、AES-256 + PBKDF2 100,100 次）→ 2023-03-01 正式承认保险库备份被窃并披露加密范围缺陷；2025-02 学术界复盘（arXiv 2502.04287）。迭代次数不均（官方承认）：新默认 600,000，但大量历史账户仅 5,000 次、**部分低至 1 次**。加密结构缺陷（研究者分析）：AES-256-CBC 无完整性保护（无 MAC），"结构上不足以对抗离线爆破"。教训：KDF 全员强制高参数无降级路径、密文必须带完整性保护、URL/标题等元数据纳入加密、**厂商"无证据"公告不可作安全结论**（2022-12 公告三个月后被 2023-03 公告推翻）。
- **KeePass CVE-2023-32784（NVD API 实测）**：影响 KeePass 2.x < 2.54；即使工作区已锁定或已退出，仍可从内存转储（进程转储、pagefile.sys、hiberfil.sys、整机 RAM）恢复**明文主密码**（首位字符无法恢复）；CVSS 3.1 7.5（2023-05-15 发布）；修复：2.54 改用不同 API 调用并插入随机字符串。PoC：https://github.com/vdohney/keepass-password-dumper 。定性：前提是攻击者已能读本机内存/页面文件，不扩大网络暴露面，但对"拿到硬盘镜像即可破解"的威胁模型是实打实的削弱。当前最新 2.61.1。
- **KeePass 假冒分发（已证实，多家独立厂商）**：事件 A——2023-10 Google 广告投放 Punycode 同形异码域假冒官网（带"已验证"绿标），分发木马化安装器（FakeBat/SectopRAT）并诱导上传 KDBX 文件（Malwarebytes/Ars Technica/BleepingComputer/海德堡大学 URZ）；事件 B——2025-05 WithSecure 披露 **KeeLoader** 假安装器（**持受信任 CA 签名的有效数字证书**，活动约 8 个月，从 KDBX 与浏览器提取凭据、内存加载 Cobalt Strike、投放 Qilin 勒索）。keepass.info 本体从未被入侵——最大攻击面是**分发渠道**（搜索广告、同形域）。对策：仅官网下载、保持 ≥2.54、核对作者签名。
- **Bitwarden CVE-2026-42994（GHSA-999x-2wm3-jfx8，Advisory API 实测）**：npm 渠道 bw CLI 2026.4.0 于 **2026-04-22T21:57Z 至 23:30Z（约 1.5 小时窗口）被植入恶意代码**（Checkmarx 供应链事件，疑似滥用 Bitwarden CI/CD 的 GitHub Action）；CVSS 3.1 **9.8**（CWE-78/94）。**从 bitwarden.com 官方下载渠道的桌面客户端不受影响**——同一公司同一代码库，两条分发渠道风险不同；包管理器渠道（npm/PyPI）是"版本投毒"最现实入口。缓解：锁版本+订阅 GHSA+轮换令牌。关联背景：Shai-Hulud npm 蠕虫（2025-09/2025-11 两波，自我传播窃取 npm 令牌、感染数百包，Zapier/ENS 等知名包中招）——针对开发者的凭据窃取已进化为"自传播蠕虫+真实包投毒"，**密码管理器 CLI 本身已成被投毒对象**。
- **Bitwarden 浏览器扩展 CVE**：CVE-2018-25081（跨域 iframe 自动填充；编号"2018"是预留年份非披露年份——常见误解）、CVE-2023-27974（二级域匹配填充）；均为自动填充策略缺陷而非加密缺陷，默认设置已大幅缓解。**网传"CVE-2023-24044 是 Bitwarden"已证伪**（NVD API 实测为 Plesk Obsidian ≤18.0.49，且标 disputed）。
- **1Password**：2023 Okta 事件（2023-09-29 检测、2023-10-23 披露）——员工 Mac 疑似被入侵，**仅波及员工侧应用，无用户保险库数据受影响**；定性：SaaS 厂商自身的"员工身份/CI 体系"同样是供应链一环。闭源+无可复现构建意味着用户侧无法技术性排除"厂商作恶"，安全承诺只能依赖渠道完整性、独立审计、赏金与声誉激励——对本威胁模型是结构性劣势。**网传"2023 年 Secret Key 128→256 位升级"已证伪**：256 位 AES 迁移发生在 **2013 年 3 月**（官方博客），Secret Key 至今为 **128 位熵设计**（官方支持文档）。**网传"赏金在 Bugcrowd"已过时**：2022 年起迁 HackerOne（另设 100 万美元 CTF 挑战）。
- **Vaultwarden CVE 群（2024–2026，NVD/GHSA/第三方数据库核实）**：CVE-2025-24364（admin 面板 RCE，需已认证）、GHSA-c5rv-q295-7w4g（绕过登录暴力破解保护，1.35.4 修复）、CVE-2026-27801（2FA 绕过）、CVE-2026-43912（**跨组织授权绕过**）、SSO email_verified 缺陷（仅新用户校验，账号接管路径，1.36.0 修复）等。解读：客户端加密不受影响（密文仍安全），但**独立重实现版本的服务端授权逻辑质量与官方不可同日而语**；Bitwarden 官方审计（Cure53 等）、SOC 2、白皮书**均不覆盖** Vaultwarden。权衡：换掉"厂商投毒"问题，换成"维护者信任+运维质量"问题，并非免费收益。
- **可复现构建现状（对"版本投毒检测"的意义）**：**KeePassXC 是主流开源密码管理器中唯一官方承诺并走通**——2.6.0（2020-07）changelog 明确 "Make builds reproducible [#4411]"（跨平台发布二进制的端到端逐字节复现仍有未决问题，openSUSE 2024-08 状态页记录部分非确定性来源；另于 2025-10 通过 Synacktiv/ANSSI CSPN 评估）；Bitwarden 未见官方计划（反向核实：官方文档无 reproducible 条目）；1Password 闭源结构性不可能；KeePass 2.x 无（依赖作者个人 Authenticode 签名）；Vaultwarden 可自编译但容器镜像无承诺。可复现构建是**唯一让"这个二进制=这份源码"可被第三方独立验证**的机制；没有它，开源密码管理器发布渠道安装包与源码的等价性仍要靠签名链（信任打包者）。
- **量子威胁结论（NIST FAQ + PQC 会议论文）**：Grover 算法对密钥穷举二次加速，等效密钥强度减半——**AES-256 → ~128 位量子安全**（~2^128 次量子运算）；NIST 官方立场"AES-192 与 AES-256 将在很长时间内保持安全"；工程现实：Grover 实际代价远超理论上限（需海量纠错量子比特与串行查询）。**结论：AES-256 保险库加密无量子焦虑；真实短板是主密码熵**——Argon2id 的内存困难性在量子攻击模型下仍显著抬高并行穷举成本（对 KDF 的 Grover 加速无法绕过内存带宽瓶颈）。PQC 采用现状：主流密码管理器尚未全面采用（真正需替换的是分享/密钥交换等非对称组件，RSA/ECC 会被 Shor 击穿）；Proton Mail 2026-05 上线抗量子邮件但 **Proton Pass 截至核实日未上线 PQC**；自研启示：非对称部分直接选 ML-KEM 混合方案，对称层与 KDF 保持 AES-256 + Argon2id 即达量子余量上限。
- **三级信任模型对比**：

| 信任级别 | 产品示例 | 厂商针对特定区域作恶可否被发现 | 单版本被投毒的检测手段 | 残余风险 |
|---|---|---|---|---|
| L1 闭源 SaaS/闭源官方分发 | 1Password | **不能**（无代码、无可复现构建） | 无用户侧手段；仅厂商自证+渠道+赏金 | 作恶不可检测（LastPass 公告翻车示范"只能信公告"的脆弱性） |
| L2 开源+官方编译分发 | Bitwarden 官方渠道、KeePass 2.x | 源码可审，但**发布二进制≠源码**无法逐字节证明 | 签名校验、审计、赏金；npm 类渠道尤其脆弱（CVE-2026-42994 实例） | "源码干净但构建被动手脚"技术上无法排除 |
| L3 纯本地开源+可复现构建 | KeePassXC（承诺+CSPN）、自研可达到 | **可被任何第三方验证**（逐字节比对） | 可复现构建比对+独立签名+分散分发 | 依赖（编译工具链）与用户是否真的执行比对 |

横向结论：**威胁模型是"厂商故意投毒"时，L1 不可选、L2 只能缓解、L3 才是可验证解**；历史上真实发生的投毒（KeePass 假冒站、bw CLI npm 投毒、Shai-Hulud）全部发生在**分发渠道**而非官方源码——验证链条必须覆盖"从源码到我运行的二进制"全程。

## 5. 云盘同步替代服务器专节（取自分报告 E）

**结论**：客户端端到端加密 + 云盘同步密文文件路线总体可行且安全边界清晰——只要密码库文件（如 KDBX，AES-256 + Argon2 KDF）在本地完成加解密，云盘运营商无论存储在哪、是否扫描，都拿不到明文。关键不在云盘加密能力，而在前提条件。

**零知识成立的前提条件（5 条）**：① 库文件在离开设备前已完成加密（不用"云端先存明文再同步"的任何工作流）；② 主密码高熵 + KDF 参数不调低（云盘存储副本可被离线穷举）；③ **keyfile 与库文件物理分离**——绝不放同一云盘目录，"否则等于把锁和钥匙一起寄走"，keyfile 只留本地并另路备份；④ 传输层不回退（坚果云 WebDAV 走 HTTPS，Syncthing 走 TLS；中间人风险主要来自被篡改的客户端安装包）；⑤ 知悉剪贴板/自动填充是另一条不在云盘安全模型内的攻击面。

**各云盘管道核实结论**：

| 云盘 | 官方 WebDAV/API | 国内可达性 | 免费额度对 KDBX | 结论 |
|---|---|---|---|---|
| 坚果云 | **有（正式功能）** | 好 | 1GB 上/3GB 下每月，足够 | **首选** |
| iCloud 中国区 | 无（专有客户端） | 好（云上贵州运营） | 5GB，足够 | 可用（备选） |
| OneDrive | 无 | 不稳定 | 5GB，足够 | 勉强可用 |
| Google Drive | 无 | 长期被阻断 | 15GB | 排除 |
| Dropbox | 无 | 被阻断（2010 起，2014 再度至今） | 2GB | 排除 |
| Syncthing | P2P 协议（无云端） | 好 | 无限制 | 推荐（进阶） |
| rclone crypt | 任意后端加密包装层 | 取决于底层 | 不新增限制 | 推荐（进阶） |
| 阿里云盘 | OpenAPI 申请制，无 WebDAV | 好 | — | **不推荐**（第三方桥接封号风险） |
| 百度网盘 | 无 | 好 | — | **不推荐**（违规凭据注入+逆向协议） |

- **坚果云 = 首选密文管道**（官方帮助 https://help.jianguoyun.com/?p=2064 与流量帮助 p=29 核实）：WebDAV 是正式功能（文档甚至以 WPS 为例，未对密码库用途设限）；必须使用**应用密码**（网页端：账户信息→安全选项→第三方应用管理→添加应用密码），主账号密码不外泄、可按应用单独吊销——主密码与同步凭据分离，泄露互不波及；**免费版每月上传 1GB/下载 3GB**（单 KDBX 月消耗个位数 MB 级，完全够用；新设备首次整库下载同样远低于 3GB）；限速免费 600 次/付费 1500 次每 30 分钟（KDBX 低频单文件操作远低于限制）；单请求文件数上限 750、单文件上传上限 500MB；专业版约 199.8 元/年（官网直购，App Store 渠道约 233 元/年；30GB 空间不限流量——价格以购买页实时显示为准，页面正文未能直接抓取）。国内速度属第一梯队（国内厂商境内数据中心，定性判断）。
- **rclone crypt**（https://rclone.org/crypt/ 核实）：客户端加密包装层，本身不存数据，包装在任意后端（WebDAV/本地目录，可多层嵌套）之上；**文件内容** NaCl SecretBox（XSalsa20 + Poly1305），64KiB 分块独立认证，开销约 0.03%；**文件名** EME（ECB-Mix-ECB）AES-256 确定性加密，目录名默认也加密（standard/obfuscate/off 三模式）；密钥由口令经 scrypt（N=16384, r=8, p=1）派生；**rclone.conf 中口令仅"轻度混淆"存储，务必对 rclone.conf 本身加密或妥善保管**；不加密的元数据：文件大小（±16 字节）、修改时间——对单个 KDBX 影响极小。坚果云接入：WebDAV 后端 `vendor = other`，URL 填 `https://<你的坚果云WebDAV服务器地址>/dav/`（域名需查其帮助中心词条，帮助页 2064 未列出），凭据用应用密码；rclone 内置 pacer 自动退避限速。Windows 用法：`rclone sync 本地路径 加密远端:路径` 定时同步，或 `rclone mount`（需 WinFsp）挂载为盘符。
- **Syncthing**（https://syncthing.net/ 与 docs.syncthing.net v2.1.0 核实）：MPL-2.0 开源 P2P 持续同步；官方明确**没有中央服务器**，"你的数据从不存储在你的计算机之外的任何地方"；TLS 传输，支持对不可信设备启用额外加密层。**Android 官方客户端现状（GitHub API 核实）**：官方 syncthing-android 仓库**已归档（archived: true），最后推送 2024-12-03**——"官方 Android 停更"传闻属实（2024-12 起停止维护并从商店下架）；社区分支 **Syncthing-Fork（researchxxl/syncthing-android，即原 Catfriend1 分支迁址）活跃维护**（最后推送 2026-10-22，未归档），经 F-Droid 与 GitHub Releases 分发，是事实上的官方继任者——"移交社区"表述准确。iOS 无官方客户端（第三方 Möbius Sync 等付费方案，不在核实范围）。架构代价：需至少两台设备同时在线，工程上用一台常开节点（NAS/树莓派/旧笔记本/最便宜 VPS）作"伪云端"；发现与中继由社区公共设施提供、不存文件内容。
- **iCloud 中国区**：云上艾珀（贵州）运营（2018-02-28 起，数据中心贵安新区），境内速度快；**ADP（高级数据保护）在中国大陆不可用**（公开报道与用户实测，官方支持页未列地区清单）——但 KDBX 客户端加密使这点不构成密码库机密性缺口，ADP 影响的是 iCloud 里的其他数据；不建议把 keyfile/主密码便签等敏感文件与 KDBX 放进未开 ADP 的 iCloud。Windows 经 Microsoft Store "Windows 版 iCloud"（新版要求 Windows 11+）。
- **排除项细节**：阿里云盘官网/开发者门户**未提供任何面向个人用户的官方 WebDAV**；有公开案例——用户使用 AList 访问阿里云盘遭**永久封号**（知乎 2023-03，第三方工具违反用户协议且可无事先提醒封号）；密码库是最不能承受"突然封号且数据取不回"的资产之一。百度网盘**官方从未提供 WebDAV**，所有方案均为第三方逆向/模拟（AList Crack 模式自述"基本无法使用"；BDUSS Cookie 注入类工具把账号凭据交给第三方工具本身即安全风险），封禁期通常 1–3 个月。
- **三个推荐组合**：
  1. **组合一（最省事）：KeePassXC + 坚果云 WebDAV**——Windows/Linux 用 KeePassXC（原生 WebDAV 远程数据库或官方客户端同步目录），Android 用 KeePass2Android/KeePassDX（应用密码凭据），iOS 用 Strongbox/KeePassium；成本 0 元；风险点是坚果云政策变化，但换盘成本低。
  2. **组合二（最 paranoid）：KeePassXC + rclone crypt + 任意国内云盘**——文件名+内容双加密，云盘连"这是个密码库"都看不出；`rclone mount` 挂盘符或计划任务 sync；Android 经 Termux 跑 rclone 或密文落本地目录；代价是配置复杂度显著更高、rclone.conf 需妥善保管，仅当"文件名都不能给云盘看"是硬需求时选。
  3. **组合三（零第三方云账号）：Syncthing 自建常开节点**——常开设备（NAS/树莓派/旧电脑）+ 手机 Syncthing-Fork + 桌面组网；无云账号/月费/暴露面；代价是必须有常开节点、节点磁盘纳入备份、iOS 覆盖弱。
  4. （Apple 生态备选）组合四：iCloud Drive + KeePass 系客户端，适合 Apple 全家桶用户顺带使用。
- **成本对比（自建服务器 vs 云盘 vs Syncthing P2P，估算值）**：国内轻量 VPS 约 24–60 元/月（有公网暴露面，需防扫描打补丁，备份完全自担）；自建 NAS 设备 1000+ 元一次性 + 电费约 10–30W 常开（每年约 90–260 元估算）；**云盘密文同步免费档 0 元（坚果云专业版 199.8 元/年），零公网暴露，备份由云盘方冗余+版本历史**；Syncthing 0 元（复用常开设备），每台设备一份完整副本天然多副本。**量化结论：云盘密文同步在货币成本与暴露面上完胜；自建服务器的全部负担对"只同步一个几百 KB 文件"的需求是明显过度工程；Syncthing 是折中。**风险对价：云盘方案把"账号安全"变成关键资产——2FA 必开、云盘密码与 KDBX 主密码必须不同、定期清理授权应用、版本历史/回收站必须开启并季度演练恢复（KDBX 单文件覆盖式更新，最危险的不是泄露而是损坏/覆盖回滚；rclone 用户可用 `--backup-dir` 归档被覆盖文件）。
- **通用实施纪律（任一组合适用）**：KDBX 用中性文件名（如 `sync/data/kx.bin`）；3-2-1 备份（3 份副本、2 种介质、1 份离线）；云盘账号开 2FA、坚果云为每客户端单独生成应用密码；每季度演练"从云盘历史版本恢复 KDBX、新设备用主密码打开"；切换云盘时 KDBX 文件本身即全部数据，随时可换同步通道；出现"conflicted copy"立即用 merge 而非覆盖；密钥文件与 KDBX 分渠道分发（F4）。

## 6. 批量导入/导出与迁移矩阵摘要（取自分报告 G）

**各软件导入能力要点**：

- **1Password**：Web/桌面导入器支持 Chrome/Firefox/Edge/Brave/Safari、Bitwarden、Dashlane、KeePass、KeePassXC、Keeper、LastPass、RoboForm 及 **1PUX** 全平台导入；CSV 仅限 Login/Credit Card/Secure Note 三类；移动端 iOS 26+/Android 14+ 支持凭据交换标准（CXP）直接互迁（含 passkey）。**重要发现（负向）**：官方 CLI 参考文档**已不再收录 import/export 命令**——旧文档地址 301 后 404（curl 实测）；`op import` 可用但处于"官方文档不背书"状态（第三方迁移指南实测示例存在 + Secfault Security 审计报告可见 op-import-export 模块佐证），格式权威清单无法从官方获取，实施前须本地 `op import --help` 实测。
- **Bitwarden**：`bw import <format> <path>`（`--formats` 机器可读全列表）；Web vault 导入器支持 60+ 格式（1Password 1pif/1pux、KeePass kdbx/KeePass 2 xml、KeePassX csv、Keeper、LastPass、ProtonPass json、RoboForm、Chrome/Edge/Firefox/Safari csv、Enpass csv/json、Avast/Avira 等）。**对 1Password 的 1pux 导入官方指南明示：附件不随导入**（"Upload file attachments to the new vault individually"），Sends 需重建。
- **KeePassXC**：**CLI 有 import/export 子命令**（与常见误解相反）：`export [选项] <数据库>` 输出 stdout 默认 XML；`import <xml> <新数据库>` 仅 XML→新建 KDBX4；`attachment-export --stdout`/`attachment-import` 单附件粒度。GUI 侧 CSV 导入带列映射向导。限制：CLI 不支持 CSV 导入导出；1PUX 无任何入口（需经 Bitwarden 或 KeePass 2 XML 中转）。
- **Vaultwarden**：复用 Bitwarden 全部客户端与导入导出格式；作为第三方服务端，个别新格式（1pux 解析）历史上出现过兼容性问题（社区反馈，未逐项复核）。
- **Infisical**：**不存在 `infisical import` 命令**（CLI 参考核实）；官方途径 `secrets set --file <路径>` 一次只吃一个文件；平台侧 external migrations 与 40+ 目标 secret syncs 是平台对平台同步。
- **gopass**：无跨管理器批量导入命令；`gopass convert` 仅后端迁移（转换 RCS 后端会丢部分 git 历史）；迁移桥是第三方 pass-import（40+ 来源，目标端含 gopass）。

**导出能力与明文安全控制横向对比**：

| 软件 | 明文导出前的确认 | 明文风险警告 | stdout 流式（避免落盘） | 加密导出选项 |
|---|---|---|---|---|
| 1Password | 重输账户密码（SSO 走 IdP） | 有（"Delete them when you are done with them"） | 无（脚本化组合命令可到 stdout） | **无**（官方原句 "Exported data files are not encrypted. They are stored in plaintext."） |
| Bitwarden | 重输主密码/邮箱验证码（CLI 由登录态背书） | 有（推荐 encrypted json；"delete the file immediately after use"） | **有**（`--raw`） | **有**（Account-restricted 与 Password-protected 两档；`zip` 含附件） |
| KeePassXC | 打开库凭据即确认 | 弱（无额外警告页） | **有**（CLI export 原生 stdout） | 天然（KDBX 加密，但"加密导出到新文件"需另建库） |
| Infisical | 登录态 | n/a（get 有 --plain 辨识） | 有（CLI 天然 stdout） | n/a |

Bitwarden 导出字段细节：仅 json 系导出含 cards/identities/passkeys/SSH keys（CSV 不含）；trash 与 Sends 任何格式都不导出；旧版 passkey（2024.3.1 前创建）导出"不应作为长期备份"；`zip` 仅限个人库。1Password 桌面导出：CSV 只导出 Login 和 Password 两类且字段受限；passkey 桌面端**不可**导出（官方建议逐网站重建；仅移动 CXP 可带）。

**两两迁移路径表**（✅ 直接支持｜🔄 需中转格式｜❌ 不支持；三条硬事实：① Bitwarden 任何导入格式不带附件；② 1Password 1PUX 明文、桌面导出无 passkey、CSV 仅 Login/Password；③ KeePassXC CSV 保留 TOTP 但丢附件与自定义属性）：

**TOTP/Passkey/附件字段保留速查**（截至 2026-10-25）：

**F9 空白点结论**：市场上**没有现成工具**能"扫描散落文件/脚本/环境变量 → 识别 → 导入密码库"——gitleaks/trufflehog 只出"泄漏报告"（**trufflehog 不支持环境变量源**：`pkg/sources` 目录逐项核实为 git/filesystem/docker/s3/gcs/github/gitlab/jenkins/circleci/postman/syslog/stdin 等，无 env；要覆盖 env 需自行导出快照到临时文件再 filesystem 扫描，注意残留）、Infisical 只吃单个 .env、dotenv 系只有目录树合并小工具（recursenv：Rust 向上遍历合并 .env；envmerge：多 .env 合并保注释——均不做密钥识别/导入）。**自研 F9 有真实价值。**引擎现状：gitleaks v8.30.1（MIT，30.3k★，git/dir/stdin 三模式，5 种报告格式，`--baseline-path` 存量降噪，235 规则；README 警告已 **feature complete** 进维护期）、trufflehog v3.99.7（AGPL-3.0，28.7k★，911 检测器，20+ 凭据类型活体验证）、detect-secrets（Apache-2.0，4.7k★，基线管理模式）。

**F10 行业现状**：**加密归档导出是全行业空白**——没有任何一家提供官方加密归档导出（1PUX 明文、CSV 明文、Dashlane/Enpass/LastPass 亦明文）；Bitwarden 最接近（`zip` 含附件 + `encrypted_json --password` + `--raw`，但"附件+加密 JSON"无一步合成单一归档命令）；KeePassXC 以 KDBX 天然加密全量补位。**自研实现"默认加密导出+可选明文"即可超越全部基准产品。**迁移枢纽结论：**Bitwarden 为第一迁移枢纽，KeePassXC 为附件保全与离线备份落点**；1Password 迁入能力尚可但 CLI 文档不透明且无加密导出，不宜作枢纽；Infisical 对象模型与凭据库不同构，仅在"开发者 secrets"子域有价值。

## 7. 最终建议（两条路线，选择留给用户）

### 路线 A：直接使用现有软件

**首选：组合方案——KeePassXC + 坚果云 WebDAV（或 Syncthing）为主库，CLI 场景加配 gopass（或自托管 Infisical）。**

理由：① 该组合对用户核心约束（F2 本地加解密、F3 云端只存密文、F4 密钥文件不上云、F6 零服务器、国内云盘管道）全部满足且软件费 0——KDBX 文件+云盘是 KeePass 生态原生形态、Enpass 证明了同构商业路线 10 年可行；② KDBX 是开放格式、天然加密全量导出（含附件/TOTP/历史），无锁定风险、迁移出口永远存在；③ KeePassXC 是唯一有可复现构建承诺 + ANSSI CSPN 审计的密码管理器，直接命中"厂商投毒"威胁模型的 L3 信任级；④ gopass `gopass env`（MIT）补齐 F8 唯一硬缺口，其 `--stdin` 变体规避 environ/ps 泄露路径；⑤ 冲突安全有 KDBX 条目级合并机制兜底（分报告C §7.3）。

**备选：Bitwarden 官方自部署（Lite 或标准版）。**

理由：若更看重 F1 浏览器填充的成熟度与一体化体验（1Password 式全家桶：扩展+移动填充+TOTP+Send+紧急访问）、且愿意运维一台服务器，Bitwarden 是唯一"全功能+私有部署+强审计背书"的平衡点（Lite 200MB RAM 可跑在树莓派/NAS）；须接受 F8 缺口（个人库无注入原语，`bw run` 已移除；严格注入语义需另购/另用 BSM `bws run`）、TOTP/附件 Premium 隐藏收费点、以及 Server 侧 CVE 跟版压力。**不推荐**：1Password（闭源 L1 不可验证+F10 明文导出+国内仅国际卡支付）、LastPass（安全记录与信任修复）、Vaultwarden 用于有合规要求的场景（无审计背书、2024–2026 授权 CVE 密集、不对数据丢失负责）、阿里/百度网盘作同步管道（封号/违规风险）、Google Drive/Dropbox（国内阻断）。

### 路线 B：自研 SuperPasswdKey

自研的正当性来自调研证实的差异化点（均非臆测）：

1. **F8 以开源实现 `op run` 全语义**（引用与值分离、子进程注入、退出即清、输出遮蔽、.env 引用化可入库）——KeePass 生态全缺、Bitwarden 个人库缺、Dashlane 未证实；开源范本有 pass-cli（GPL-3.0）/gopass env/infisical run/bws run/dotenvx run，但 Windows+Git Bash 开箱即用者仅 infisical/dotenvx，且均绑定各自平台。
2. **F9 "扫描→识别→去重→分类→导入"全链路**（.env/shell rc/systemd/compose/CI 变量/环境变量快照/私钥文件）——市场空白（trufflehog 不支持 env 源、gitleaks 进维护期、Infisical 无 import）。
3. **F10 默认加密归档导出 + 可选明文（显式 flag+重输主密码+stdout 流式）**——全行业空白，实现即超越全部基准产品。
4. **独立可自定义密钥文件（F4）**——除 KeePass 系外全行业仅 1Password 以固定 Secret Key 近似实现且不可自定义；自研差异化点。
5. **可复现构建 + 零遥测 → L3 信任级**——结构性证伪"厂商投毒"，KeePassXC 之外无人做到。
6. **双形态统一**：同一加密内核同时支持自建服务器轨（零知识）与云盘文件轨（无服务器），市场上无单一产品同时做好两条轨（Bitwarden 系需服务器、Enpass 无 CLI、Infisical 非零知识）。

**可直接复用的组件与参照**（均经分报告核实）：加密内核底座 **age**（X25519，v1.3.2 含 ML-KEM 后量子混合，MIT/BSD）+ **SOPS 文件格式思想**（只加密值、多接收者、Shamir 密钥组）；KDF/算法对齐 Bitwarden/KeePassXC（Argon2id + AES-256-GCM 或 XChaCha20-Poly1305，AEAD 强制）；F8 参照 `op run` 语义六条设计结论（分报告A §6.8：引用与值分离/子进程包裹器/默认遮蔽/威胁边界文档化/机器身份最小授权/inject 产物 0600 用后即删）+ `bws run`（state 加密、POSIX 兼容细节）+ `gopass env --stdin/--file`；F9 引擎内嵌 gitleaks 规则 TOML（静态抽取），detect-secrets 基线思想做增量；导入导出中介格式对齐 Bitwarden CSV/JSON 与 1PUX；KDBX 读写可直接用生态库（保客户端群复用）；服务器轨参照 Bitwarden Lite（200MB RAM 级单镜像、多数据库后端）而**非** Infisical 模型（服务端持钥与零知识红线冲突，仅借鉴其 run/importer UX）；Vault/OpenBao 仅在需要动态密钥/PKI 时作为外围组件。

**自研代价（如实）**：加密实现与内存清理的正确性责任全在自己（CVE-2023-32784 根因即 .NET 字符串残留，语言选型影响红线 #5 可达性）；跨平台客户端尤其 F1 自动填充引擎工作量巨大（1Password 最深护城河；KeePass 系移动端匹配精度弱于专有引擎）；可复现构建有未决工程难题；开发周期与长期维护投入远超路线 A。

**结论**：若首要诉求是"今天就可用、零运维、零订阅费"，走路线 A（KeePassXC+坚果云+gopass 组合）；若 F8/F9/F10 的空白点、独立密钥文件与"完全自主可控+可验证信任链"是硬需求，且接受开发周期，则路线 B 成立——详细需求基线见姊妹文档《自研需求基线_SuperPasswdKey.md》。最终选择由用户决定。
