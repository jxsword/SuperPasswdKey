# 分报告 E：用国内云盘同步替代自建密码管理服务器的可行性与安全注意事项

- 调研子任务：T5（云盘同步专题）
- 调研日期：2026-10-25
- 背景假设：私有部署密码库（KDBX 等格式），客户端本地加解密，云盘仅作为"密文管道"同步，云端只见密文。
- 链接核实约定：所有标注「核实: 2026-10-25 可达」的 URL 均在本调研环境实测访问成功；未能成功访问的如实标注现象。搜索引证（未直接抓取正文的）单独注明。

---

## 1. 核心结论先行

**"客户端端到端加密 + 云盘同步密文文件"路线总体可行，且安全边界清晰**：只要密码库文件本身（如 KDBX，AES-256 + Argon2 KDF）在本地完成加解密，云盘运营商无论存储在哪、是否扫描，都拿不到明文。关键不在云盘加密能力，而在三点前提（见第 4 节）。

综合可用性、成本、国内网络可达性，推荐组合（详见第 6 节）：

1. **KeePassXC + 坚果云 WebDAV**（最省事，免费额度对单个 KDBX 文件绰绰有余）
2. **KeePassXC + rclone crypt + 任意国内云盘**（最 paranoid，文件名也加密）
3. **Syncthing 自建常开节点**（零第三方云账号，需一台常开设备）

**免费额度（核实自官方帮助 p=29）**：
- 免费版：**每月上传 1GB、下载 3GB**，按账号周期清零不累积。

- 未发现坚果云官方对"WebDAV 用途"做密码库类限制；其帮助文档明确面向第三方应用场景（文档中甚至以 WPS 为例）。

**国内速度**：国内厂商、数据中心在境内，同步速度在国内网络环境下属于第一梯队；本报告未做跨地域实测，此点为基于其国内节点的定性判断。

- **对本场景的意义**：即使无法启用 ADP，KDBX 文件本身已是客户端加密——云盘运营商看到的是密文，ADP 与否不影响密码库的机密性；ADP 影响的是你存在 iCloud 里的**其他**数据。建议不要把 keyfile/主密码便签等其他敏感文件与 KDBX 放进未开 ADP 的 iCloud。

**Windows 访问方式（核实自官方支持页 HT204283，2026-08 更新）**：从 Microsoft Store 下载"Windows 版 iCloud"，可在文件资源管理器中访问 iCloud Drive 文件（含 KDBX 同步目录）；新版要求 Windows 11 或更高。

### 2.6 Syncthing——P2P 直连，无云端账号

- 官网: https://syncthing.net/ （核实: 2026-10-25 可达）
- 官方文档: https://docs.syncthing.net/ （核实: 2026-10-25 可达，文档版本 v2.1.0）
- 源码: https://github.com/syncthing/syncthing （主程序；本报告经 GitHub API 核实仓库存在）
- 简介：开源（MPL-2.0）设备间 P2P 持续同步工具。官方明确表述：**没有中央服务器**，"你的数据从不存储在你的计算机之外的任何地方"（核实自官网首页）；传输经 TLS 加密，文档还支持对不可信设备启用额外加密层（Untrusted Device Encryption，核实自 docs）。

**架构含义（对本场景）**：
- 无第三方云账号 = 无云盘运营商扫描、封号、倒闭三类风险，密文管道问题直接消失（设备间另有 TLS）。
- 代价：**需要至少两台设备同时在线**才能同步。手机改了密码库，家里的电脑不在线就同步不过去。工程上通常用一台常开节点（NAS、树莓派、旧笔记本或一台最便宜的 VPS）作为"伪云端"，Syncthing 本身不产生月费（除非用 VPS）。
- 发现与中继（discovery/relay）由社区公共基础设施提供，不存储文件内容（核实自 docs：discovery/relay 为辅助服务，非中央存储）。

**Android 官方客户端现状（核实: 2026-10-25 经 GitHub API）**：
- 官方 Android 应用仓库 `syncthing/syncthing-android` **已归档（archived: true），最后推送 2024-12-03**——"官方 Android 应用停更"传闻属实：2024 年 12 月起官方停止维护并从应用商店下架。
- 社区分支 **Syncthing-Fork（researchxxl/syncthing-android，即原 Catfriend1 分支迁址）活跃维护中（最后推送 2026-10-22，未归档）**，经 F-Droid 与 GitHub Releases 分发，是当前 Android 端事实上的官方继任者。传闻中"移交社区"的表述准确。
- iOS 无官方客户端（第三方 Möbius Sync 等付费方案，不在本报告核实范围）。

**Windows/Linux 桌面**：官方提供 Windows、Linux、macOS、BSD 原生支持（核实自官网平台列表），Windows 有 SyncTrayzor 等托盘封装，Linux 发行版多可直接包管理器安装。

### 2.7 rclone——任意云盘外加一层客户端加密

- 官网: https://rclone.org/ （核实: 2026-10-25 其 /crypt、/webdav 子页均可达）
- 官方文档: https://rclone.org/docs/ （域名同站可达）
- 源码: https://github.com/rclone/rclone （MIT 许可）
- 简介：开源云存储命令行工具，支持 70+ 后端，核心能力是 `sync`（单向/双向同步）、`mount`（挂载为盘符）、`bisync`（双向）。

**rclone crypt 工作原理（核实自 https://rclone.org/crypt/ ）**：
- crypt 是**客户端加密包装层**：本身不存数据，包装在任意后端（WebDAV、本地目录均可，甚至可多层嵌套）之上，上传前在本地加密、下载后本地解密；直接访问底层网盘只能看到乱码。
- **文件内容**：NaCl SecretBox（XSalsa20 流加密 + Poly1305 完整性认证），文件分 64KiB 块，每块独立认证，开销约 0.03%。
- **文件名**：EME（ECB-Mix-ECB）AES-256 加密，确定性加密；目录名默认也加密（整个路径）；三种模式 standard/obfuscate/off。
- 密钥由口令经 scrypt（N=16384, r=8, p=1）派生；**注意 rclone.conf 中口令仅"轻度混淆"存储，务必对 rclone.conf 本身加密或妥善保管**——rclone 的加密强度取决于配置文件安全。
- 不加密的信息：文件大小（误差 16 字节内）、修改时间——元数据仍可能泄露，但对单个 KDBX 文件影响极小。

**Windows 用法**：`rclone sync 本地路径 加密远端:路径` 做定时同步，或 `rclone mount 加密远端:路径 *`（需 WinFsp）挂载为盘符后由密码管理器像操作本地盘一样读写。

**与坚果云 WebDAV 兼容性**：rclone WebDAV 后端配置 `vendor = other`（rclone 内置 vendor 列表为 fastmail/nextcloud/owncloud/sharepoint 等，坚果云按"other"接入；核实自 https://rclone.org/webdav/ ），URL 填 `https://<你的坚果云WebDAV服务器地址>/dav/`（具体地址见坚果云官方帮助），凭据用坚果云应用密码。**限速对策**：坚果云官方限制为免费 600 次/30 分钟、付费 1500 次/30 分钟（核实自 help.jianguoyun.com/?p=2064），rclone 有内置 pacer（`--webdav-pacer-min-sleep` 等）可自动退避；对单 KDBX 文件场景几乎不可能触发。

## 4. 安全注意事项专节

### 4.1 "云端只见密文"成立的前提条件（零知识验证标准）

KDBX 整库 AES-256 加密使云盘"拿不到内容"并非自动成立，需同时满足：

1. **库文件在离开设备前已完成加密**：KDBX 由主密码（+可选 keyfile）经 KDF（Argon2d，KeePassXC 默认）派生密钥整库加密，云盘任何时刻只接触密文。前提是**不要使用"云端先存明文、再同步"的任何工作流**。
2. **主密码强度与 KDF 参数足够**：云盘运营商（或拿到其存储副本的攻击者）可以对密文离线穷举。主密码必须高熵（长口令/密语），KeePassXC 默认 Argon2d 参数不建议调低。
3. **keyfile 与库文件物理分离**：若使用 keyfile，绝不能把 keyfile 和 KDBX 放在同一云盘目录——那等于把锁和钥匙一起寄走。keyfile 只留在本地设备并另路备份。
4. **传输层不回退**：坚果云 WebDAV 走 HTTPS；Syncthing 走 TLS。中间人风险主要来自被篡改的客户端安装包，应从官网/官方渠道下载并校验签名。
5. **剪贴板与自动填充是另一条攻击面**，不在云盘安全模型内，但使用中需知悉（密码管理器自带剪贴板自动清除）。

**结论**：满足以上条件时，云盘运营商对密码库内容具备与任何随机文件相同的可见性——零知识成立；运营商能看到的只剩元数据（见 4.3）。

### 4.2 云账号自身安全（密文方案的"新攻击面"转移到账号）

- **2FA 必开**：坚果云/OneDrive/iCloud/Google 均支持两步验证。密码库主密码再强，账号被撞库接管 = 攻击者拿到密文并可在云端静默替换/回滚文件。
- **独立密码**：云盘登录密码与 KDBX 主密码必须不同；坚果云场景下 WebDAV 使用应用密码（已核实官方机制），可实现"同步凭据与账号密码分离"，某第三方应用凭据泄露不影响账号整体。
- **版本历史与回收站**：KDBX 是单文件覆盖式更新，**最危险的不是泄露而是文件损坏/覆盖回滚**（手机旧版本覆盖电脑新版本）。坚果云提供历史版本与回收站（付费版保留期更长）；OneDrive/Dropbox 亦有版本历史。开启并定期演练"从历史版本恢复"。rclone 用户可用 `--backup-dir` 把被覆盖文件归档到带日期的目录。
- **设备管理**：定期在云盘账号设置里清理不再使用的授权应用与设备（坚果云的第三方应用管理列表即此用途）。

### 4.3 风险清单

| 风险 | 说明 | 缓解 |
|---|---|---|
| 元数据扫描 | 云盘可见：文件名（KDBX 建议用中性命名）、文件大小、修改频率、IP 与设备指纹。运营商可推断"这是密码库并在何时被改" | 内容不可得即无实际危害；介意者用 rclone crypt（文件名/目录名全加密，已核实机制） |
| 账号被封 | 同步中断（数据通常仍在，但取回困难）；第三方桥接工具场景可能数据直接取不回 | 只用官方通道（坚果云 WebDAV 正当用途）；另存独立备份（第 5 节 3-2-1 原则） |
| 云盘倒闭/服务变更 | 坚果云免费政策历史上多次调整（空间/流量规则），未来可能继续变化 | KDBX 本身可移植：换个云盘=换个同步目标，客户端无感；保留最近一份本地副本 |
| 云端文件被替换/回滚 | 有账号控制权者（或运营商内部作恶）可替换密文 | 密码管理器打开时校验完整性（KDBX 有 SHA-256 头校验+HMAC，损坏会拒绝打开而非静默导入错误数据）；保留多代历史版本 |
| rclone.conf 泄露 | rclone 口令仅轻度混淆存储于配置文件 | 对 rclone.conf 加密（`rclone config` 支持配置文件密码）或将其置于系统凭据保护之下 |

### 4.4 成本与安全面对比：自建服务器 vs 云盘密文同步 vs Syncthing P2P

| 维度 | 自建服务器（VPS） | 自建 NAS | 云盘密文同步（坚果云等） | Syncthing P2P |
|---|---|---|---|---|
| 货币成本 | 约 24–60 元/月起（国内轻量 VPS 行情，估算值） | 设备 1000+ 元一次性 + 电费约 10–30W 常开（估算：每年约 90–260 元电费） | 免费档 0 元；坚果云专业版 199.8 元/年 | 0 元（复用现有常开设备）；用 VPS 当节点则同 VPS 列 |
| 维护负担 | 系统更新、证书续期、服务运维 | 系统更新、盘健康监控 | 近零 | 近零（常开节点一次配置） |
| 公网暴露面 | 有公网端口，需自行防扫描/打补丁 | 家庭内网穿透若做公网映射则同样有暴露面 | **零**（客户端主动连云盘出站） | **零**（P2P 打洞/TLS；中继不存内容） |
| 备份责任 | 完全自担（须自建备份策略） | 完全自担（RAID≠备份） | 云盘方承担存储冗余；版本历史可用 | 每台设备一份完整副本，天然多副本 |
| 信任依赖 | 自己的运维能力 | 自己的运维能力 | 云盘账号安全（2FA）+ 客户端加密 | 自有设备不丢失 |
| 单点故障 | VPS 宕机=同步中断 | NAS/NAT 环境问题 | 云盘服务变更 | 常开节点离线=同步暂停（数据不丢） |

**量化结论**：云盘密文同步在货币成本与暴露面上完胜（成本≈0、零公网暴露），代价是把"账号安全"变成了关键资产；自建服务器的全部负担（补丁、证书、暴露面、备份）对这个"只同步一个几百 KB 文件"的需求而言是明显过度工程；Syncthing 是两者之间的折中——零第三方但需要一台常开设备。

## 5. 通用实施建议（任一组合都适用）

1. KDBX 库文件用中性文件名（如 `sync/data/kx.bin`），不叫 `passwords.kdbx`。
2. 3-2-1 备份：至少 3 份副本、2 种介质、1 份离线（本地另存 + 云盘 + 偶尔导出到 U 盘）。
3. 云盘账号开 2FA；坚果云为每个客户端单独生成应用密码。
4. 每季度演练一次：从云盘历史版本恢复 KDBX、在新设备上用主密码打开。
5. 切换云盘或担心封号时，导出路径始终存在：KDBX 文件本身即全部数据，随时可换同步通道。

## 6. 推荐组合与跨平台覆盖

### 组合一（推荐，最省事）：KeePassXC + 坚果云 WebDAV
- Windows/Linux：KeePassXC 原生支持 WebDAV 远程数据库（或配 rclone/坚果云官方客户端做同步）。
- Android：KeePass2Android / KeepassDX 支持坚果云 WebDAV（凭据用应用密码）。
- iOS：Strongbox / Keepassium 支持 WebDAV。
- 成本 0 元；免费流量额度对单 KDBX 文件月消耗约 MB 级，绰绰有余；风险点是坚果云政策变化，但换盘成本低。

### 组合二（推荐，最 paranoid）：KeePassXC + rclone crypt + 任意国内云盘
- rclone crypt 包在坚果云（vendor=other）或其他可达云盘上，文件名+内容双加密，云盘连"这是个密码库"都看不出来。
- Windows：`rclone mount` 挂载加密远端为盘符，KeePassXC 当本地文件打开；或计划任务跑 `rclone sync`。
- Linux：同上（mount 或 sync + cron）。
- Android：可用 Termux 跑 rclone，或退而求其次让 rclone 把密文同步进手机本地目录后由 KeepassDX 打开。
- 代价：配置复杂度显著高于组合一；rclone.conf 需妥善保管。**仅当"文件名都不能给云盘看"是硬需求时才选**。

### 组合三（零第三方云账号）：Syncthing 自建常开节点
- 一台常开设备（NAS/树莓派/旧电脑）跑 Syncthing，手机（Syncthing-Fork）与桌面（KeePassXC 所在机）都与它组网，KDBX 目录设为共享文件夹。
- Windows/Linux：Syncthing 官方支持（已核实）；Android：Syncthing-Fork（官方应用已归档、社区分支活跃，已核实 2026-10-22 仍在维护）。
- 无云账号、无月费、无暴露面；代价是必须有常开节点，且节点磁盘也要纳入备份。iOS 覆盖弱（需第三方付费应用）。

### 组合四（Apple 生态备选）：iCloud Drive + KeePass 系客户端
- 中国区 iCloud 由云上贵州运营、境内速度快；ADP 在中国大陆不可用（据公开报道与用户实测），但 KDBX 客户端加密使这一点不构成密码库的机密性缺口。
- Windows 经"Windows 版 iCloud"（Microsoft Store）访问 iCloud Drive；macOS/iOS 原生。
- 适合 Apple 全家桶用户顺带使用；不建议把其他敏感明文一并存入未开 ADP 的 iCloud。

**总排序建议**：普通个人/小团队 → 组合一；安全要求高且愿意折腾 → 组合二；完全不接受第三方云盘 → 组合三；Apple 重度用户 → 组合四。
