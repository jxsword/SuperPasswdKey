# Android 真机安装测试方案（M1c 前置，spike e2e 真机口径）

- 日期：2026-10-27 ｜ 适用：`feature/android-spike` 合并后的任意含 sp-kffi 的构建
- 目的：把模拟器口径的 spike 结论（KDF 1045~1124ms / VmHWM delta≈68MiB / 8 项断言）落到真机；
  回填 SP-N-301/302（DR-009 列为 M1 前置）；为 M1b/M1c（Autofill 精度清单）准备设备侧条件
- 关联：docs/reviews/android_spike_结论报告_2026-10-27.md、design_docs/13 §4.4/4.6、design_docs/14 §6

## 1. 设备与前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 设备 | Android 9.0+（minSdk 28），arm64-v8a | 建议 ≥2 台：1 台原生/Pixel 类 + 1 台厂商定制（三星/小米/OPPO 任一，R14-3 厂商差异） |
| RAM 记录 | 越低越好（对照用） | ≤4GB 设备可顺带验证 68MiB KDF 峰值是否引发卡顿/LMK |
| 开发者选项 | 设置→关于手机→连点版本号 7 次 | 厂商 ROM 可能藏在不同路径 |
| USB 调试 | 开发者选项内开启；首次连接主机弹授权 | MIUI 等需同时开"USB 安装（USB debugging install）" |
| 主机侧 | 本仓库 Android 环境已部署（adb/NDK/cargo-ndk 自检过） | `adb devices` 能看到设备 |
| 口令纪律 | **测试专用 throwaway 口令**；绝不把真实密码库装上测试设备 | 凭据只走环境变量/intent extra，不进命令行历史之外的任何持久层（SRS 红线 #5） |

## 2. 构建与安装（adb 途径，开发口径）

当前 `android/app/src/main/jniLibs/` 只有 x86_64（模拟器口径），真机需先补 arm64-v8a：

```bash
# 1. 交叉编译 arm64 .so（spike 已验证 release 1.9MB；真机测试用 debug 以便 run-as）
cargo ndk -t aarch64-linux-android --platform 28 -- build -p sp-kffi
mkdir -p android/app/src/main/jniLibs/arm64-v8a
cp target/aarch64-linux-android/debug/libsp_kffi.so \
   android/app/src/main/jniLibs/arm64-v8a/

# 2. 构建 APK（debug 构建 = debuggable，run-as 可用）
cd android && ./gradlew.bat :app:assembleDebug

# 3. 安装（USB 连接后）
adb install -r app/build/outputs/apk/debug/app-debug.apk

# 4. 生成 fixture（凭据走环境变量；真机测试建议换新口令）
mkdir -p build
SP_TEST_DB_PASSWORD=<新测试口令> SP_TEST_ENTRY_PASSWORD=<新测试条目值> \
  cargo run -q -p sp-kffi --example make_spike_vault -- build/test_vault.kdbx

# 5. 推送 fixture（/data/local/tmp → run-as 进应用私有目录）
adb push build/test_vault.kdbx /data/local/tmp/
adb shell run-as com.superpasswdkey.spike mkdir -p files
adb shell run-as com.superpasswdkey.spike cp /data/local/tmp/test_vault.kdbx files/
adb shell rm /data/local/tmp/test_vault.kdbx   # 用完即清

# 6. 启动 e2e（凭据经 intent extra；Git Bash 下必须 MSYS_NO_PATHCONV=1）
MSYS_NO_PATHCONV=1 adb shell am start -n com.superpasswdkey.spike/.MainActivity \
  --es db_password <口令> --es entry_password <条目值> --es entry_username demo-user

# 7. 采集结果（两路，互为备份）
adb logcat -d -s SPIKE
adb shell run-as com.superpasswdkey.spike cat files/result.txt
```

注：Git Bash 的 adb 路径参数需 `MSYS_NO_PATHCONV=1`（`/data/...` 会被本地路径转换）；PowerShell/cmd 无此问题。

无开发者选项的普通侧载（备用途径）：把 app-debug.apk 拷到设备点击安装（允许未知来源）——但
无法用 run-as 推 fixture，需设备有文件管理器把 kdbx 放到应用可读位置，**spike 壳不支持**，
故此途径仅 M1b 之后（应用内导入）适用，本方案不展开。

### B. KDF 实测回填（SP-N-301/302 真机数字，本方案核心）

采集并记录（每台设备各一行）：

| 采集项 | 方法 |
|---|---|
| 开库耗时（3 次，取冷/热分离） | result.txt 的 openDb #1/#2/#3 |
| 内存峰值 | VmHWM delta（openDb #1 行） |
| 主观流畅度 | 开库期间 UI 是否冻结/ANR（spike 壳主线程调用，本就预期冻结——记录时长是否可接受） |
| 设备档案 | `adb shell getprop ro.product.model ro.product.cpu.abi ro.build.version.release` + RAM（设置→关于手机）；**关闭省电模式**（降频会污染数字，如实记录当时模式） |

判定线：64MiB Argon2id **≤3s**（DR-008 ③的真机口径）。同时记录"解锁体验可接受线"（建议 ≤2s）作 KDF 参数定稿输入（design_docs/13 §4.4）。内存关注点：峰值 ≈68MiB + 应用基线，在 ≤3GB RAM 设备上是否有系统杀后台/明显卡顿。

## 5. 测试后清理（安全纪律）

1. `adb uninstall com.superpasswdkey.spike`（连同私有目录数据一起删除）；

2. 确认设备上无残留：`adb shell run-as com.superpasswdkey.spike ls files/`（卸载后应报错=已清）。
3. 本机 `build/test_vault.kdbx` 与 fixture 口令视为一次性，可删；**不要**把真机测试口令用于任何真实库。
4. jniLibs/arm64-v8a/*.so 已 gitignore，不入库。

### 执行中的 HyperOS/Android 16 拦截点（记录供后续真机复用）

1. **安装**：`INSTALL_FAILED_USER_RESTRICTED` → 需手机端开"USB 安装"（用户已操作）。
2. **`input keyevent`**：SecurityException INJECT_EVENTS（shell 注入被 HyperOS 收紧）→ C4 改用 Activity 切换路径。
3. **`pm clear`**：SecurityException CLEAR_APP_USER_DATA → 直接 uninstall（等价清数据）。
4. spike 壳 log 中 "[非真机: x86_64 emulator]" 为写死文案（壳为模拟器构建时写的），本表以设备档案为准；M1b 壳改造时改为动态读取 Build 信息。

### KDF 参数定稿输入（SP-N-302，→ **DR-010 已定稿，2026-10-27**）

- 真机（骁龙 8s Gen 3，中高端 SoC）：t=8/p=4 ≈ **2.2–2.5s**，贴 ≤3s 线；低端设备预计超线。
- 体验定稿线：用户确认 **≤2s**。
- 决策（DR-010）：终态=**init 校准**（t∈[2,8]/m=64MiB/p=4，目标 ~1s；KeePassXC 官方同口径、桌面 SP-N-302 同策略）；过渡=FFI 默认 **t=4/p=4**（中端 ~1.1–1.3s；仅影响新建库）。
- 结论建议：移动端默认参数在 M1b 时降为 t=4/p=4（64MiB 内存下限不动，红线 #6），真机低端复核后定稿 DR-010。~~待定~~ → 已按 DR-010 执行。
