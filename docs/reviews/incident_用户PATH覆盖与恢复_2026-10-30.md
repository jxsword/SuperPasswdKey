# 事件记录：用户 PATH 被覆盖为仅安装目录（2026-10-30，已恢复）

## 概要

v0.3.0 发布测试期间，`sp-cli` NSIS 安装器在本机测试时把 **HKCU 用户 PATH 整体覆盖为仅安装目录**，导致用户其余 PATH 条目全部丢失。当日从早于损害的进程环境中完整恢复（49 条 / 1460 字符），并修复两个根因缺陷。

## 时间线（+0800）

- 10-30 约 06:45–07:25：NSIS 静默安装测试（多次运行安装器）——每次运行都触发覆盖。锚点：其后提交 `0665599` @ 07:28:01。
- 10-30 白天：install.ps1 测试（此时 PATH 已是损害态，备份/恢复均在损害态之间进行，无法还原原值——第二个失误：备份时机错误且首次备份只记了长度未落盘值）。
- 10-30 晚（本会话）：用户报告 → 核实机制 → 从进程环境恢复 → 根因修复。

## 根因（两个叠加缺陷）

1. **NSIS `ReadRegStr` 长值返回空**：NSIS 字符串上限（NSIS_MAX_STRLEN=1024）内读不到超长注册表值——`ReadRegStr` 失败且输出变量为**空串**。旧 PATH 段逻辑对"空"的处理是 `StrCpy $R0 "$INSTDIR"`（视为无 PATH）→ `WriteRegStr` 整体覆盖 → **原 PATH 全部丢失**。用户 PATH 超过 1024 字符，必然触发。
2. **测试纪律缺陷**：备份在第一次覆盖之后才落盘（首次仅记录长度 1383 未落盘值）；且恢复校验只检查了测试条目缺失，未校验完整性。

## 恢复过程

- 恢复源：**早于损害时间启动的进程环境**（ZCode 主进程继承的合成 PATH = 系统+用户完整快照）。方法：合成 PATH 逐条减去系统 PATH（HKLM 未受影响）→ 剩余即用户段（保持原顺序）；剔除 Git Bash 会话注入的 MSYS 目录（mingw64/usr/bin 等）、去重；SP 安装目录按损害期间状态保留在末尾。
- 结果：49 条 / 1460 字符写回 `HKCU\Environment\Path`（REG_SZ，绝对路径形态；原值若含 %VAR% 展开形已展平——功能等价）。关键工具（git/python/adb/sp/scoop）逐一验证可解析。

## 预防（随本事件落地的修复）

1. `scripts/add-path.ps1`（新）：.NET `RegistryKey` 读原始值（**无长度上限**）→ 幂等追加 → 按**原值类型**写回（REG_EXPAND_SZ 保留）→ 广播；含"新值必须以旧值为前缀"的硬守卫。
2. `sp-cli.nsi`：PATH 段弃用 NSIS 原生读写，改为调用随包 `add-path.ps1`（nsExec）。
3. `install.ps1`：空读守卫（读到空但注册表存在非空值 → 中止不覆盖）。
4. 教训入册：**任何"读-改-写"用户全局状态的代码，必须把"读取失败/异常空值"处理为中止而非走"空值=首次使用"分支**；破坏性测试前先落盘完整状态。

## 遗留

- 恢复值为**展开后的绝对路径**形态（原值若含 %VAR% 引用已展平）——功能等价；如需恢复引用形态请手工调整。
- 损害期间丢失后无法从本机找回的条目：无（进程环境快照覆盖了完整原值；若用户发现缺项，请对照其他早于 10-30 06:45 启动的终端 `$env:Path` 补齐）。
